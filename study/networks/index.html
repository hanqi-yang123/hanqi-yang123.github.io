1.2 什么是因特网：两种描述#

定义：①具体构成——由一群遵循 TCP/IP 协议的 ISP 按松散层次结构组成的"网络的网络"；②服务描述——为分布式应用提供通信服务的基础设施。

机制：构成描述指导通信功能的实现（ISP 内部与 ISP 之间如何互联），服务描述指导服务接口的定义（向上提供可靠有序的 TCP 服务与不可靠的 UDP 服务）。

例：写聊天软件只需调用套接字把数据交给因特网；运营商规划的是 ISP 之间的链路与互联点。前者用服务描述，后者用构成描述。

1.2.1 具体构成：端系统、链路、交换机#

定义：运行网络应用的设备称端系统（主机），经通信链路与分组交换机相连，并通过 ISP 接入因特网；链路速率以 bit/s（bps）度量。

机制：发送端把报文切块并加首部形成分组；交换机从入链路收、向出链路转发，路由器用于网络核心、链路层交换机多用于接入网；分组经过的链路与交换机序列称路径。所有部件都运行协议，最重要的是 TCP 与 IP，协议族统称 TCP/IP。

例：从校园网访问 www.princeton.edu，路径为网卡→楼内交换机→边缘路由器→地区 ISP→骨干 ISP→对方校园网。

1.2.2 服务描述：分布式应用与套接字#

定义：涉及多台端系统相互交换数据的应用称分布式应用（QQ、联机游戏、Web），只运行在端系统，不运行在分组交换机中。

机制：端系统提供套接字接口（API），规定软件如何请求因特网把数据交付给另一台端系统上的目的进程。

例：浏览器向套接字写 GET /index.html，由操作系统按目的 IP、端口、协议封装发出，浏览器不关心中间路由。

1.2.3 协议与协议三要素#

定义：协议定义通信实体之间交换的报文格式与次序，以及收发报文或其他事件时所采取的动作。

机制：三要素——语法（字段结构、编码，如首部多少字节）、语义（字段含义与应答动作）、同步／时序（何时发、次序、速率匹配）。缺一则通信无法收敛。

例：TCP 三次握手：SYN 报文含序号与标志位（语法）；SYN=1 请求建链、ACK=1 表示确认号有效（语义）；先 SYN、后 SYN+ACK、再 ACK，且超时重传（时序）。

1.2.4 标准化#

定义：因特网标准由IETF研发，标准文档称 RFC；IEEE 802 系列（以太网、WiFi）由 IEEE 制定。

例：IP 见 RFC 791，TCP 见 RFC 793。

1.3 网络边缘与接入网#

定义：接入网把端系统物理连接到其边缘路由器——端系统到任何远程端系统路径上的第一台路由器。

机制：DSL 与 FTTH 每户独占一段媒体；HFC 与无线接入是共享媒体，共享意味着高峰时每户可用速率下降。

1.3.1 数字用户线 DSL#

定义：利用电话公司已有的双绞铜线（每户一条）同时承载数据与电话。

机制：频分复用——高频段作下行（<24 Mbps）、中频段作上行（<2.5 Mbps）、低频段留给双向电话；用户侧 DSL 调制解调器把数据变成高频音，局端 DSLAM 分离数据与语音，因此电话公司即用户的 ISP；受衰减与串扰限制，距局端须在 5～10 英里（约 8～16 km） 内。

例：边打电话边下载互不干扰，因为二者占用不同频段。

1.3.2 混合光纤同轴 HFC#

定义：主干用光纤、入户用同轴电缆的电缆接入系统，称混合光纤同轴。

机制：用户侧需电缆调制解调器，局端需 CMTS；典型下行 30 Mbps、上行 2 Mbps（DOCSIS 2.0 规定下行 42.8 Mbps、上行 30.7 Mbps）；关键特征是共享广播媒体，一条同轴上的 500～5000 户共享带宽，上行还需多址协调。

例：某段同轴 2000 户，200 户同时下载时平均每户仅得约 1/200 的下行带宽。

1.3.3 FTTH、拨号与卫星#

定义：FTTH（光纤到户）把光纤铺到家庭；拨号借电话线经调制解调器接入；卫星用于偏远覆盖。

机制：FTTH 多采用无源光网络（PON），速率数百 Mbps 至 Gbps；拨号约 56 kbps 且占用电话线；同步卫星单程传播约 120 ms，不适合高实时业务。

例：农村宽带通常选 FTTH 或 4G 固定无线，而非成本更高的 DSL 延伸。

1.3.4 以太网与 WiFi#

定义：以太网是最流行的有线局域网接入，使用双绞铜线；IEEE 802.11（WiFi）是无线局域网接入，终端距基站几十米。

机制：以太网速率为 10 Mbps→100 Mbps→1 Gbps→10 Gbps，交换式以太网中每台主机独享端口带宽；WiFi 典型 11 Mbps 或 54 Mbps（后续标准可达数百 Mbps），同一 AP 下用户共享空口时间。

例：24 口千兆交换机每口独享 1 Gbps；改接一台 54 Mbps AP，则全室共享该空口速率。

1.3.5 蜂窝接入#

定义：移动通信公司提供的广域无线接入，复用蜂窝电话网，覆盖半径数万米。

机制：3G 典型 2 Mbps；4G（含 LTE）下行 100 Mbps、上行 20 Mbps，靠 OFDM 与多天线提高频谱效率。

1.4 物理媒体#

定义：发送器—接收器对通过物理媒体传播电磁波或光脉冲发送比特，分导引型（沿固体媒体）与非导引型（空气、真空、外层空间）。

机制：同一路径的不同链段可用不同媒体（城际光纤、入户双绞线），媒体只决定比特如何变成信号，与上层协议无关。

1.4.1 导引型媒体#

定义：双绞线（两根绞合铜线）、同轴电缆（同心导体）、光纤（拉细的玻璃纤维，导引光脉冲）。

机制：双绞线最便宜、绞合抗干扰，速率 10 Mbps～10 Gbps，取决于线径与距离；同轴抗干扰较好，可作导引型共享媒体；光纤衰减小、抗电磁干扰、难窃听、误码率低，速率几十至几百 Gbps，适合长距离骨干。

例：楼间用光纤、楼层内用双绞线、有线电视入户用同轴。

1.4.2 非导引型媒体#

定义：依靠天线辐射与接收电磁波，无需固体线路。

机制：能穿墙、连移动用户、长距承载，但受遮挡与干扰；卫星分同步（GEO，约 36000 km，单程传播约 120 ms）与低轨（LEO，时延小、需星座组网）。

例：海上平台靠卫星回传，时延大但别无选择。

1.5 网络核心：分组交换#

定义：网络核心是由分组交换机与链路构成的网状网络，任务是把分组从发送侧边缘路由器送到接收侧边缘路由器。

机制：两个关键功能——路由（决定路径，由路由算法完成，分布式、秒级）与转发（把分组从入端口移到出端口，查转发表，逐包、纳秒级）。移动数据有两种基本方式：分组交换与电路交换。

1.5.1 存储转发#

定义：分组以链路最大速率传输，用时 L/R（L 为分组比特数，R 为链路速率），称传输时延。

机制：交换机必须收到整个分组后才能开始发送第一个比特（便于校验、确认与重传，不做边收边发）；故单个分组经 N 段链路需 N· L/R，P 个分组背靠背共 (P+N-1)L/R（流水线重叠）。

例：L=1000 B=8000 bit、R=1 Mbps、3 段链路：单包 3×8=24 ms；10 个包 (10+3-1)×8=96 ms，而非 240 ms。

1.5.2 输出缓存、排队与丢包#

定义：每条相连链路对应一个输出缓存（输出队列），暂存待发分组。

机制：到达速率超过出链路速率即排队；缓存有限，队列满时新到分组（或已排队分组之一）被丢弃，即丢包；大量分组集中到达时排队与丢包最严重。

例：校园网出口 1 Gbps，晚高峰聚合流量瞬时达 1.2 Gbps，队列填满后丢包，用户表现为卡顿与重传。

1.5.3 转发表与 IP 地址#

定义：每个端系统有 IP 地址，发送端在首部写入目的 IP；路由器用转发表把目的地址（或其前缀）映射为输出链路。

机制：路由器取目的地址的一部分做前缀匹配查表转发，转发表由路由选择协议自动生成与更新。

例：目的地址 140.180.223.42 命中前缀 140.180.0.0/16，转发表指示从 3 号端口发往上游 ISP。

1.6 电路交换与复用#

定义：电路交换在通信期间预留端到端资源（链路速率、交换机容量），典型为传统电话网；分组交换按需使用资源。

机制：建链时建立专用电路并预留恒定速率，结束释放。注意区分：链路是物理媒体（信道），可划分为若干子信道；电路是其中一条子信道。划分方式为 FDM（每连接专用一个频段，频段宽度称带宽）或 TDM（时间划分为帧，帧划分为时隙，每连接专用一个时隙）。

例：双方沉默时 64 kbps 电路仍被独占，别人无法使用——这是静默期效率低的根源。

1.6.1 FDM 与 TDM 的定量关系#

定义：TDM 每条电路速率 = 帧速率 × 每时隙比特数 =R/ 时隙数；FDM 每条电路带宽 = 总频宽 / 频段数。

机制：TDM 用户周期性独占全速率，FDM 用户持续占用部分带宽；与同步 TDM 相比，分组交换用户使用链路的模式不固定（有数据才发）。

例：10 Mbps 链路、4 个时隙，每电路 2.5 Mbps；帧速率 500 帧/s 时每时隙 2.5×10⁶/500=5000 bit；传 100 kB（800000 bit）需 800000/2.5×10⁶=0.32 s =320 ms。

1.6.2 分组交换与电路交换的取舍#

维度 电路交换 分组交换
资源 预留、独占 按需、共享
时延 建立后恒定，端到端传输时间与链路数无关 逐跳存储转发，排队时延可变
适用 语音等恒定速率实时业务 突发数据（Web、文件、视频流）
效率 静默期浪费 统计复用，容纳更多用户
缺点 建链复杂、成本高 拥塞抖动、可能丢包，无服务质量保证

机制：分组交换的效率来自统计复用——不按峰值预留，而按实际需求共享，轻载时更快；代价是失去带宽与时延的确定性。

例：10 Mbps 链路、20 个各需 1 Mbps 的用户：电路交换最多接入 10 个；分组交换 20 个都能建链，但同时活跃超过 10 个即拥塞（见 1.11 例 4）。

1.7 网络的网络：ISP 层次结构#

定义：端系统经接入 ISP 接入因特网，接入 ISP 又须与地区 ISP、第一层 ISP 逐级互联，形成多层结构。

机制：因特网是"网络的网络"，无严格层次、无统一管理机构；互联既靠技术（IP）也靠商业关系（客户—提供商、对等）。

1.7.1 关键构件#

定义：PoP（存在点）是低层 ISP 接入高层 ISP 的地方；多宿是一个低层 ISP 接入多个高层 ISP；对等是同层 ISP 直连、互不付费；IXP 是第三方建立的多 ISP 对等交换点；内容提供商网络（如 Google）自建全球网络与多个互联数据中心。

机制：多宿使某一高层故障时仍可收发分组；对等与 IXP 让流量绕过上层、降低费用与绕行时延；内容提供商把内容推到离用户更近处。

例：某校园网同时接入 CERNET 与电信（多宿），在 IXP 与某 CDN 对等后，访问该 CDN 不再绕行第一层 ISP，时延与费用同时下降。

1.8 四种时延与流量强度#

定义：结点总时延 d_nodal=d_proc+d_queue+dₜᵣₐₙₛ+dₚᵣₒₚ，依次为处理、排队、传输、传播时延。

机制：四者量级与影响因素不同，必须分别估算；其中只有排队时延是随机的。

例：网页请求中处理时延通常可忽略，传播时延由距离决定，传输时延由文件大小与带宽决定，拥塞时排队时延可能占主导。

1.8.1 处理时延#

定义：d_proc 为检查首部、决定去向、检查比特差错的时间，微秒级或更低。

机制：由路由器 CPU 与查表硬件决定，与分组大小、链路速率关系不大。

例：核心路由器单包处理约 1～10 μs；10 Gbps 链路上 1500 B 分组每 1.2 μs 就到达一个，处理时延已不可忽略。

1.8.2 排队时延与流量强度#

定义：d_queue 是在输出缓存等待传输的时间；a 为分组到达速率（pkt/s），流量强度为 La/R。

机制：La/R>1 时队列无界增长、时延趋于无穷，设计系统时不得大于 1；La/R≤1 时排队时延取决于到达的突发性（均匀到达低、成批突发高）；接近 1 时时延急剧上升，实际因缓存有限转为丢包，丢包比例随流量强度增加。

例：L=1500 B=12000 bit、R=10 Mbps：a=500 pkt/s 时 La/R=0.6；a=900 pkt/s 时 La/R=1.08>1，队列持续增长直至丢包。

1.8.3 传输时延#

定义：dₜᵣₐₙₛ=L/R，把分组全部比特推上链路所需时间。

机制：只与分组长度和链路速率有关，与距离无关。

例：1500 B 在 100 Mbps 上为 120 μs，在 2 Mbps 上为 6 ms。

1.8.4 传播时延#

定义：dₚᵣₒₚ=d/v，v 约为光速的 2/3～1 倍（2×10⁸∼3×10⁸ m/s）。

机制：由距离与媒体决定，与带宽、分组大小无关；是卫星链路时延的主要来源，在校园网内可忽略。

例：d=10000 km =10⁷ m、v=2.5×10⁸ m/s，dₚᵣₒₚ=40 ms。

1.8.5 端到端时延#

定义：路径上所有结点的结点时延之和，另计端系统的处理与应用时延。

机制：N 段链路、忽略处理与排队时为 N· L/R+Σᵢ dᵢ/vᵢ。

例：3 段 2 Mbps、1500 B 分组、总长 10000 km：传输 18 ms ＋ 传播 40 ms ＝ 58 ms。

1.9 丢包与吞吐量#

1.9.1 丢包#

定义：输出缓存已满时到达的分组被丢弃。

机制：丢包比例随流量强度上升；衡量结点性能既要看时延，也要看丢包概率。

例：出口队列仅 1 MB，突发 2000 个 1500 B 分组（约 3 MB）集中到达时，超出缓存的部分全部被丢弃。

1.9.2 吞吐量#

定义：单位时间内成功交付到目的端的数据量（bps）；平均吞吐量 = 文件总比特数 / 总时间。

机制：链状路径的吞吐量为瓶颈链路速率 \minR₁,…,Rₙ；有共享链路时取 \minRₛ,R_c,R_pub/U（U 为共享用户数）。吞吐量取决于实际流过的速率与干扰流量，标称高速的链路也可能成为瓶颈。

例：Rₛ=2 Mbps、R_c=1 Mbps，则吞吐量 1 Mbps，传 10 MB 文件需 8×10⁷/10⁶=80 s。

1.10 协议分层与协议栈#

定义：把系统按功能划分为若干层次，每层实现一种服务，并向上一层提供服务模型；各层协议合称协议栈。

机制：每层通过"在本层执行动作 ＋ 使用下层服务"实现功能。优点：结构化地确定各部分关系，模块化使升级维护容易（改一层实现不影响他层）。缺点：高层可能冗余低层功能；某层可能需要其他层的信息，违反层次分离。协议层可用软件、硬件或二者结合实现。

例：网卡从百兆换千兆，IP、TCP、HTTP 软件无需修改，只需驱动适配。

1.10.1 五层协议栈#

层次 数据单元 功能 典型协议
应用层 报文 message 网络应用之间交换信息 HTTP、FTP、SMTP、DNS
传输层 报文段 segment 进程之间传输报文 TCP、UDP
网络层 数据报 datagram 主机之间传送分组，含路由选择 IP、ICMP、路由协议
链路层 帧 frame 相邻结点之间传输 以太网、PPP、802.11
物理层 比特 在媒体上逐比特传送 双绞线、光纤、无线

机制：主机五层、路由器三层、链路层交换机两层；应用层与传输层是端系统软件，物理层与链路层在网卡中实现，网络层为软硬件混合。

1.10.2 OSI 七层模型#

定义：ISO 的开放系统互联模型在应用层与传输层之间增加表示层（压缩、加密、编码转换）与会话层（数据交换定界、同步、检查点与恢复）。

机制：因特网把这两层功能留给应用程序开发者，故实际协议栈为五层。

例：HTTPS 的加密与 gzip 压缩都在应用层内部完成，并没有独立的表示层协议。

1.10.3 封装#

应用层   [        报文 message        ]
传输层 [TCP首部][  报文  ]             → 报文段
网络层[IP首部][ 报文段 ]               → 数据报
链路层[帧首][ 数据报 ][帧尾]           → 帧
物理层 1011011100101…（比特流）

定义：分组由首部字段与有效载荷字段（通常来自上一层）组成，跨层时逐层添加（发送）与删除（接收）首部，称为封装。

机制：因特网把复杂性放在网络边缘，核心只做转发，因而交换机只实现两层、路由器三层，这正是封装思想的体现。

例：1000 B 报文 ＋20 B TCP ＋20 B IP ＋14 B 以太网首部 ＋4 B 帧尾 =1058 B 帧在线路上传输。

1.11 典型例题#

例 1 关于路由协议的错误描述#

选项：(A) 计算数据包从源到目的的路径；(B) 查询转发表，决定数据包从路由器转发出去的端口；(C) 根据计算出的路径配置路由器转发表；(D) 分布式运行在路由器上。

答案：B。 路由协议负责算出路径并据此配置转发表（A、C），且由多台路由器分布式运行（D）。"查询转发表、决定从哪个端口转发"是转发，属数据平面的逐包操作。口诀：路由＝算路（控制平面、秒级），转发＝查表搬包（数据平面、纳秒级）。

例 2 哪种时延对端到端时延贡献最大#

选项：(A) 传输延迟；(B) 传播延迟；(C) 排队延迟；(D) 不好说。

答案：D。 四者的相对大小随场景变化：轻载时处理与排队可忽略，时延主要由传输与传播构成，大文件走低速链路时传输时延占主导；跨洋或卫星链路中传播时延占主导（同步卫星单程约 120 ms）；拥塞链路上排队时延可从微秒涨到数百毫秒。只能说排队时延变化范围最大、最难预测，不能说它总是最大。

例 3 哪种不是 ISP 的连接方式#

选项：(A) 双方连接内容提供商网络实现连接；(B) 通过客户—提供商方式连接；(C) 双方接入因特网交换点（IXP）实现连接；(D) 双方通过对等方式连接。

答案：A。 ISP 互联的三种标准方式是客户—提供商、对等、在 IXP 对等。内容提供商网络（Google、Netflix 等）是 ISP 的客户或对等方，ISP 之间不会"通过连接内容提供商网络"彼此互联。

例 4 10 Mbps 链路与 20 个 1 Mbps 用户#

答案：C（20 位用户均建立连接，数据通信产生较多丢包和较大时延）。

分组交换不预留带宽，建链时不做带宽检查，故 20 位用户都能建链（排除 A、B），也没有人获得固定 0.5 Mbps（排除 D）。链路容量 10 Mbps，只能同时承载 10 路活跃的 1 Mbps 流。设每位用户以 p=0.1 的概率处于发送状态，同时活跃数 X∼ B(20,0.1)，则 P(X>10)=Σₖ₌₁₁²⁰\binom20k0.1ᵏ0.9²⁰⁻ᵏ≈7×10⁻⁷。多数时刻无拥塞，但一旦同时活跃超过 10 个，链路瞬时过载，队列排满后丢包，表现为较大时延与丢包。若改成电路交换，则只能接入 10 户，第 11 户的请求被拒绝——这正是"分组交换支持更多用户、但不保证服务质量"。

例 5 1500 B 分组经 3 段链路的端到端时延#

已知 L=1500 B、R=2 Mbps、v=2.5×10⁸ m/s，三段长 5000／4000／1000 km，忽略处理与排队时延。

答案：58 ms。

  1. 单位换算：L=1500×8=12000 bit，R=2×10⁶ bit/s。
  2. 单段传输：dₜᵣₐₙₛ=12000/2×10⁶=6×10⁻³ s =6 ms。
  3. 存储转发，3 段共 3×6=18 ms。
  4. 传播：5×10⁶/2.5×10⁸=20 ms，4×10⁶/2.5×10⁸=16 ms，10⁶/2.5×10⁸=4 ms，合计 40 ms。
  5. 总计：18+40=58 ms。若不存储转发（边收边发）则为 6+40=46 ms。

例 6 两段链路背靠背发送两个分组#

服务器经两条链路（Rₛ、R_c，各段传播时延 dₚᵣₒₚ）向客户端发送两个长 L 的分组。

(1) 若 Rₛ<R_c，客户端收到两个分组第一个比特的间隔：L/Rₛ。

设 t=0 发分组 1：其首比特到达客户端为 L/Rₛ+dₚᵣₒₚ+L/R_c+dₚᵣₒₚ；分组 2 首比特到达为 2L/Rₛ+dₚᵣₒₚ+L/R_c+dₚᵣₒₚ，相减得 L/Rₛ。因 Rₛ<R_c，路由器发送快于到达，分组 2 到达时链路已空，不会排队，间隔由瓶颈链路的传输时间决定。

(2) 若 R_c<Rₛ，不排队的条件：T≥ L/R_c-L/Rₛ。

分组 1 在路由器发送结束于 L/Rₛ+dₚᵣₒₚ+L/R_c；分组 2 收完到达路由器为 (L/Rₛ+T)+L/Rₛ+dₚᵣₒₚ=2L/Rₛ+T+dₚᵣₒₚ。要不排队须 2L/Rₛ+T≥ L/Rₛ+L/R_c，即 T≥ L/R_c-L/Rₛ。因 R_c<Rₛ，右端为正，说明必须等足够久，否则第二个分组在路由器缓存积压。

例 7 语音分组化的"产生到还原"时延#

Host A 把语音编码为 256 kbps 码流，以 112 B 成包，经 512 kbps 链路（传播时延 10 ms）送到 B，B 收完整包立即解码。

答案：15.25 ms（按分组首比特计，最坏情形）。

  1. 分组长 112×8=896 bit。
  2. 成包时延：该比特须等整包凑齐，896/256×10³=3.5 ms。
  3. 传输时延：896/512×10³=1.75 ms（整包发完才能解码）。
  4. 传播时延 10 ms。
  5. 合计 3.5+1.75+10=15.25 ms。

若该比特在分组末尾，只需再等 1.75+10=11.75 ms；分组内各比特的时差在 11.75～15.25 ms 之间，平均 13.5 ms。考试通常答 15.25 ms 并注明"含成包时延"。这也是实时语音要用 20 ms 左右短分组的原因。

例 8 tracert 输出的平均 RTT 与跨洋链路#

末行 23 321 ms 274 ms 337 ms www-tmp.Princeton.EDU [140.180.223.42]，共 23 跳。

(1) 平均 RTT =(321+274+337)/3=932/3≈310.7 ms；单程约 155 ms。共 23 跳，其中 22 跳是路由器，第 23 跳即目的主机（按"路由节点"计为 22 台，按跃点计为 23）。

(2) 跨太平洋链路在 14 跳 210.25.189.18（27 ms）与 15 跳 210.25.189.50（177 ms）之间，RTT 突增 177-27=150 ms。取单程 150/2=75 ms、v=2×10⁸ m/s，则 d=dₚᵣₒₚ· v=75×10⁻³×2×10⁸=1.5×10⁷ m =15000 km，与中美跨太平洋距离（约 1 万～1.5 万公里）相符。其后主机名依次出现 internet2.edu、magpi.net、Princeton.EDU，也印证 14→15 跳为越洋点。

1.12 常见题型与解题模板#

模板 A：时延计算（最高频）

  1. 画链路图，标出每段的 Rᵢ、dᵢ、vᵢ 与分组数 P。
  2. 单位统一：B→bit 乘 8；km→m 乘 10³；1 Mbps =10⁶ bit/s；1 ms =10⁻³ s。
  3. 传输时延 L/R 每段链路各算一次（存储转发）；传播时延 d/v 按各段距离分别算。
  4. 题目说"忽略"的处理与排队时延置 0。
  5. 多分组：(P+N-1)L/R（忽略传播）。
  6. 复核量级：传播时延常为几十 ms，传输时延常为 μs～ms，异常即查单位。

模板 B：分组交换 vs 电路交换

  1. 电路交换先求每条电路速率（TDM 为 R/ 时隙数），传输时间 = 数据量 / 电路速率，与链路数无关，另加建链时间。
  2. 分组交换用 (P+N-1)L/R 加逐段传播时延。
  3. 用户数：电路交换最多 ⌊ R/Rᵤₛₑᵣ⌋ 户；分组交换全部可接入，拥塞概率用二项分布 P(X>k) 估算。
  4. 结论落在"统计复用提高利用率、但牺牲时延与带宽保证"。

模板 C：吞吐量与瓶颈

  1. 串联链路取 \minRᵢ；有共享链路取 \minRₛ,R_c,R_pub/U。
  2. 传输时间 = 文件比特数 / 吞吐量。
  3. 检查标称高速链路是否被干扰流量占满。

模板 D：RTT／tracert 类

  1. 平均 RTT = 该行 3 个测量值之和 /3；单程取一半。
  2. 跳数 = 输出行数；路由器数 = 行数 -1。
  3. 找相邻两跳 RTT 差值最大处即长距离链路，用 d=dₚᵣₒₚ· v 反推距离并与地理距离对照。

1.13 易错点与辨析#

  1. 路由 vs 转发：算路径、配转发表是路由（控制平面）；查表搬包是转发（数据平面）。问"路由协议的功能"不能选"查询转发表"。
  2. 传输时延 ≠ 传播时延：L/R 与分组大小、带宽有关而与距离无关；d/v 与距离、媒体有关而与带宽无关。加大带宽不能减小传播时延。
  3. "端到端传输时间与链路数无关"只适用于电路交换；分组交换逐跳存储转发，每跳都要重新完整发送。
  4. 存储转发公式别丢 -1：P 个分组、N 段链路为 (P+N-1)L/R，单个分组才是 N· L/R。
  5. 流量强度分子是比特率：La/R 中 a 的单位是 pkt/s；把 a 当 bit/s 会差三个数量级。
  6. 流量强度趋近 1 时时延不会真的无穷大：缓存有限，超出即丢包。
  7. 带宽一词多义：链路带宽指 bps；FDM 中的带宽指频段宽度（Hz）。
  8. 设备层次：主机五层、路由器三层、交换机两层；"路由器实现传输层"是错的。
  9. DSL 独占、HFC 共享：DSL 每户独享双绞线到 DSLAM；HFC 是同轴广播媒体，500～5000 户共享。
  10. 排队时延不可预测：其余三种可算，排队只能给统计特性，这也是分组交换不适合实时业务的原因。
  11. 丢包源于缓存满，不是链路传输出错；比特差错由链路层校验处理。
  12. 吞吐量不等于链路速率：瓶颈可能因共享与干扰出现在标称高速的链路上。

1.14 一页速记#

两种描述：①遵循 TCP/IP 的 ISP 按松散层次组成的网络的网络；②为分布式应用提供通信服务的基础设施（套接字接口）。

协议三要素：语法（格式）、语义（含义与动作）、同步（时序）；标准由 IETF 发布为 RFC；核心协议 TCP、IP。

接入网数值：DSL 下行 <24／上行 <2.5 Mbps，5～10 英里；HFC 30／2 Mbps（DOCSIS 2.0：42.8／30.7），500～5000 户共享；以太网 10 Mbps～10 Gbps；WiFi 11／54 Mbps；3G 2 Mbps；4G 100／20 Mbps。

物理媒体：双绞线 10 Mbps～10 Gbps；同轴；光纤几十～几百 Gbps；电磁波与卫星（GEO 单程约 120 ms）。

核心：路由＝算路径，转发＝查表；存储转发须收完整包；P 个分组 N 段链路用 (P+N-1)L/R。

电路交换：FDM 分频段、TDM 分时隙；每电路速率 =R/ 时隙数；传输时间与链路数无关；静默期浪费带宽。

时延 公式 量级 主导场景
处理 d_proc μs 或更低 高速路由器
排队 d_queue μs～ms，变化最大 拥塞链路
传输 L/R μs～ms 低速链路、大分组
传播 d/v ms 卫星、跨洋

流量强度 La/R：>1 队列无界；→1 时延急升，实际表现为丢包。

吞吐量：\minR₁,…,Rₙ；共享链路 \minRₛ,R_c,R_pub/U。

分层：应用（报文）—传输（报文段，进程间）—网络（数据报，主机间）—链路（帧，相邻结点）—物理（比特）；主机五层、路由器三层、交换机两层；封装＝逐层加首部。

必背数值：光速 3×10⁸ m/s，光纤中约 2×10⁸ m/s；1500 B =12000 bit；同步卫星 36000 km。

2.1 应用层协议原理#

2.1.1 网络应用程序体系结构#

定义/结论：应用体系结构由开发者设计，规定应用如何组织在各端系统上，与固定的网络五层结构不同；主流是 C/S 与 P2P。前提是应用软件只运行在端系统，路由器等核心设备不在应用层起作用。

机制解释：C/S 有一台总是打开、IP 周知的服务器服务众多客户，客户间不直接通信；资源集中、发现简单，但有单点故障、扩容压力、流量不均、时延大。P2P 让间断连接的主机对直接通信，具自扩展性、省服务器带宽，但安全、性能、可靠性难保障。

例：教务系统是 C/S；BitTorrent 是 P2P；微信混合——登录走 C/S，音视频可 P2P。

2.1.2 进程与套接字#

定义/结论：通信主体是进程，跨主机进程靠交换报文；发起者是客户进程，等待者是服务器进程，P2P 中一个进程可兼两角色。进程通过套接字收发报文。

机制解释：套接字是应用层与传输层之间的接口，也是应用与网络之间的 API。定位进程需 IP 地址 + 端口号两重标识。熟知端口：HTTP 80、SMTP 25、FTP 21/20、DNS 53、POP3 110、IMAP 143、Telnet 23。

例：浏览器（临时端口 49152）连服务器 80 端口；服务器以"源 IP+源端口+目的 IP+目的端口"区分客户，每个新连接建新套接字。

2.1.3 应用对传输层的四类需求#

定义/结论：需求为可靠数据传输、吞吐量、定时、安全性；因特网传输层只较好满足第一类，吞吐量与定时无保证。

需求 含义 敏感 不敏感
可靠数据传输 正确、完整、按序 文件、邮件、Web 实时音视频
吞吐量 保证最低速率 流媒体、视频会议 邮件、文件、Web（弹性）
定时 每 bit 时延上限（如 100 ms） 因特网电话、视频会议 邮件、下载
安全性 加密、完整性、鉴别 电商、登录、支付 公开静态内容

例：因特网电话要时延小于约 150 ms 但可丢包，常用 UDP 自行补偿；大文件下载用 TCP。

2.1.4 TCP 与 UDP 的服务模型#

定义/结论：因特网提供 TCP、UDP，都不提供安全。TCP 面向连接、可靠、全双工，有流量与拥塞控制；UDP 只提供最小服务。

机制解释：TCP 先握手建连、用完拆除，无差错按序交付，有流量控制（不超接收端能力）与拥塞控制（求全网公平）；不提供及时性、最低带宽、安全，SSL/TLS 在应用层补加密与鉴别。UDP 无握手、可丢可乱序、无拥塞控制，但保留报文边界、首部仅 8 字节。

例：视频会议用 UDP，丢几帧只轻微花屏；DNS 用 UDP 求快，丢了重发。

2.1.5 应用层协议的要素#

定义/结论：应用层协议规定不同端系统上的进程如何交换报文，须定义报文类型（请求/响应）、语法（字段及顺序）、语义以及发送与响应的规则。

机制解释：协议有开放（RFC 定义）与私有两类；网络应用 ≠ 应用层协议——HTTP 只是 Web 应用的组件之一。

例：取网页需 HTTP、DNS、TCP 协同，但应用层协议只管报文语义。

2.2 Web 与 HTTP#

2.2.1 HTTP 概况#

定义/结论：Web 的应用层协议是超文本传输协议，用 TCP、端口 80，是无状态协议。

机制解释：页面由对象组成，一个对象是一个文件；1 个 HTML + 5 个 JPEG 共 6 个对象，HTML 也是对象。HTML 用 URL 引用对象，URL = 主机名 + 路径。浏览器是客户，服务器存对象；HTTP 假定 TCP 可靠交付。

例：http://www.someSchool.edu/someDepartment/picture.gif 即"主机名 + 路径"，浏览器先 DNS 解析再连 80 端口。

2.2.2 持续连接与非持续连接#

定义/结论：非持续：每个请求/响应对用单独 TCP 连接，发完一个对象即关；持续：所有请求/响应复用同一连接。HTTP/1.0 非持续，1.1 默认带流水线的持续连接。

机制解释：RTT 是短分组往返时间（含传播、排队、处理，不含传输）。非持续取一个对象需 2 个 RTT（握手 + 请求响应）；持续首对象 2 RTT、其后每对象 1 RTT；流水线可连发请求，引用对象共约 1 RTT。非持续缺点：每对象新建连接、多付 RTT。

方式 N 个对象（忽略传输时延）
非持续、无并发 2N RTT₀
非持续、m 并发 2⌈ N/m⌉ RTT₀
持久、无流水线 (N+1)RTT₀
持久、流水线 3RTT₀

例（带步骤）：1 个 HTML + 3 张小图，传输时间忽略：

  1. 非持久无并发：2RTT₀+3×2RTT₀=8RTT₀；
  2. 非持久 3 并发：2RTT₀+2RTT₀=4RTT₀；
  3. 持久无流水线：2RTT₀+3×1RTT₀=5RTT₀；
  4. 持久流水线：2RTT₀+1RTT₀=3RTT₀。

2.2.3 HTTP 报文格式#

定义/结论：报文为 ASCII 文本，每行以 CRLF 结束，末行后加一个 CRLF 表示首部结束；首行是请求行或状态行，其后是首部行，空行之后是可选的实体体。

GET /somedir/page.html HTTP/1.1   <- 请求行：方法 URL 版本
Host: www.someschool.edu          <- 首部行
Connection: close
User-agent: Mozilla/5.0
Accept-language: fr
                                  <- 额外的 CRLF（空行）
                                  <- 实体体：GET 时为空
首部 作用
Host 对象所在主机（虚拟主机必需）
Connection close 非持续、keep-alive 保持
User-agent / Accept-language 浏览器类型 / 期望语言
If-Modified-Since 条件 GET 时间戳
Content-Length / Content-Type 实体字节数 / 类型

响应报文 = 状态行（版本 状态码 短语）+ 首部（Date、Server、Last-Modified 等）+ 空行 + 实体体。

状态码 含义
200 OK 成功，对象在实体体
301 Moved Permanently 永久迁移，新 URL 在 Location
304 Not Modified 条件 GET 命中，无实体体
400 Bad Request 请求无法理解
404 Not Found 文档不存在
505 HTTP Version Not Supported 版本不支持

方法：GET 取对象；POST 提交表单（数据在实体体）；HEAD 只要首部（调试）；PUT 上传覆盖、DELETE 删除（均 1.1）。

例：表单用 POST 时关键字不进 URL；改 GET 则为 /search?q=HTTP，可行但暴露。HEAD 只看 Content-Length，免传整个文件。

2.2.4 Cookie：在无状态协议上建会话#

定义/结论：HTTP 无状态便于高并发，但站点要识别用户（购物车、个性化、限访）；Cookie 用四组件在其上建立有状态会话层，代价是隐私。

机制解释：四组件为①响应中的 Set-Cookie 首部行；②请求中的 Cookie 首部行；③浏览器维护的 Cookie 文件；④站点后端数据库。用户信息存服务器数据库，发给客户的只是 ID。

例（带步骤）：

  1. A 首次访问，服务器生成 ID 1678；
  2. 数据库为该 ID 建表项；
  3. 响应加 Set-Cookie: 1678；
  4. 浏览器存入 Cookie 文件；
  5. A 再访问时自动带 Cookie: 1678，服务器查库识别。

2.2.5 Web 缓存器（代理服务器）#

定义/结论：缓存器保存最近请求过的对象副本，可不访问源服务器就满足请求；它既是服务器又是客户。

机制解释：命中直接返回；未命中则代客户回源取回、存副本再返回。作用：降低响应时间、减少接入链路流量（省费用）、减少全网 Web 流量。它存对象内容，不存用户访问记录。

例：接入链路 15 Mbps、对象 100 KB、请求率 15 次/秒时利用率约 0.8；加命中率 0.4 的缓存器后仅 60% 请求走链路，利用率降到约 0.48。

2.2.6 条件 GET#

定义/结论：缓存副本可能陈旧；条件 GET 指用 GET 方法并带 If-Modified-Since: 首部行：未修改回 304（不含对象），已修改回 200 加新对象。

机制解释：缓存器保存对象时一并记 Last-Modified，命中后带该时间戳回源确认，服务器比较当前最后修改时间决定回 304 还是 200。

例（带步骤）：

  1. 首次未命中，取回对象并记 Last-Modified；
  2. 次日命中，发 If-Modified-Since: <该时间>；
  3. 未改 → 回 304，用本地副本；
  4. 已改 → 回 200 与新对象，更新副本。

2.3 文件传输协议 FTP#

2.3.1 双连接结构#

定义/结论：FTP 用两条并行 TCP 连接：控制连接（21）传命令与响应，数据连接（20）传文件；每条数据连接只传一个文件，传完即关。FTP 是有状态协议。

机制解释：客户用临时端口主动连 21 并明文认证（USER/PASS）；传文件时才建数据连接，服务器从其 20 端口主动连客户的数据端口（主动模式）。分开的好处：不混淆数据与命令/响应、传输中仍可执行其他操作（如随时中止）；以关闭数据连接表示文件结束，允许动态创建文件。FTP 是带外控制，HTTP 是带内控制；有状态须保留当前目录与认证状态，限制并发会话数。

例：登录后控制连接常驻；列目录、下载都是"控制连接发命令 → 开数据连接传数据 → 关数据连接 → 控制连接继续可用"。

2.3.2 命令与响应#

定义/结论：控制连接以 7 bit ASCII 传命令与响应（不同于 HTTP 报文）；每个命令得三位数字响应码。

命令 含义 响应码 含义
USER / PASS 用户名 / 口令 331 用户名正确，需口令
LIST 列目录（走数据连接） 125 数据连接已开，开始传输
RETR / STOR 下载 / 上传 425 无法打开数据连接
QUIT 退出 452 写文件出错

例（带步骤）：①连 21 端口；②USER alice→331；③PASS→230；④LIST（开数据连接传列表后关闭）；⑤RETR a.pdf；⑥QUIT。

2.4 因特网中的电子邮件#

2.4.1 组成与投递#

定义/结论：电子邮件由用户代理（UA）、邮件服务器、SMTP 组成；邮件服务器是核心，每个接收方有邮箱（存已收）与报文队列（待发）。

机制解释：UA 负责撰写、阅读、回复、转发并推给发送方服务器；SMTP 送到接收方服务器并存入邮箱；接收方用邮件访问协议读取。若接收方服务器故障，报文留队列反复重试（约每 30 分钟，持续数天）。

例（带步骤）：①UA 用 SMTP 把信推到本域服务器；②报文入外出队列；③DNS 查目的域 MX 得邮件服务器名与 IP；④连其 25 端口握手传报文；⑤存入 Bob 邮箱；⑥Bob 用 POP3/IMAP/HTTP 读取。

2.4.2 SMTP#

定义/结论：SMTP 用 TCP、25 端口，命令/响应交互、持久连接，内容只能用 7 bit ASCII；发送方服务器跑客户端，接收方跑服务器端。

机制解释：三阶段——握手、传报文、关闭；响应以三位码开头（220、250、354、221）。不使用中间邮件服务器，双方直接建 TCP 连接；一条连接可传多个报文，报文以只含句点的行 CRLF.CRLF 结束。

S: 220 mail.networkutopia.com SMTP
C: HELO mail.ustc.edu.cn            S: 250 Hello
C: MAIL FROM: <alice@ustc.edu.cn>   S: 250 OK
C: RCPT TO: <bob@networkutopia.com> S: 250 OK
C: DATA   S: 354 Start mail input; end with <CRLF>.<CRLF>
C: From: alice@ustc.edu.cn
C: Subject: Test
C:                        (空行)
C: Hello Bob, this is a test.
C: .
S: 250 OK      C: QUIT      S: 221 Bye

例：带两张图的邮件，SMTP 把它们与正文放在一个报文里（MIME multipart）；含两张图的网页，HTTP 用三个响应报文分别传。

2.4.3 SMTP 与 HTTP 的对比#

定义/结论：两者都传文件、都用持久 TCP 连接，但方向、编码、报文组织不同。

维度 SMTP HTTP
方向 推（发送方主动） 拉（客户主动）
编码 限 7 bit ASCII，二进制需 base64 无限制
报文组织 所有对象一个报文 每对象一个响应报文
结束 CRLF.CRLF Content-Length / 关闭

例：这是"邮件可带附件、网页要分多次取"的根源。

2.4.4 邮件报文格式与 MIME#

定义/结论：邮件报文 = 首部行 + 空行（CRLF） + 报文体；首部必须有 From:、To:，可含 Subject:。首部是报文的一部分，与 SMTP 命令（MAIL FROM、RCPT TO）完全不同。

机制解释：为传中文、图片、附件，引入 MIME：用 Content-Type、Content-Transfer-Encoding 说明类型与编码（常用 base64），把二进制转成 ASCII 再交给 SMTP。

例：Content-Type: text/plain; charset="utf-8" + Content-Transfer-Encoding: base64，空行后是 base64 正文。

2.4.5 邮件访问协议：POP3、IMAP、HTTP#

定义/结论：SMTP 只能推，不能把信拉到 PC；用户终端又不总在线，邮箱不能放本地，故需邮件访问协议：POP3（110）、IMAP（143）、HTTP。

机制解释：

  • POP3：三阶段——特许（明文 user/pass）、事务处理（list、retr、dele）、更新（quit 后真删标记报文）；响应只有 +OK/-ERR。分下载并删除（换终端看不到）与下载并保留；跨会话无状态。
  • IMAP：报文留在服务器，可建文件夹、移动邮件，跨会话保持状态，可只取报文一部分，适合多设备。
  • HTTP：UA 就是浏览器，经 HTTP 收发邮件（Webmail），服务器之间仍用 SMTP。

例：机房用 POP3"下载并删除"读完信，回宿舍用手机就看不到；改用 IMAP 后各处状态一致。

2.5 DNS：因特网的目录服务#

2.5.1 DNS 提供的服务#

定义/结论：DNS 包括由分层服务器实现的分布式数据库与一个应用层协议，运行在 UDP、53 端口（响应超 512 字节或区域传送用 TCP）。主机有两种标识：主机名（面向人）与 IP 地址（32 bit）。

机制解释：DNS 是核心功能却在应用层实现，名字服务器部署在网络边缘，不直接与用户交互，故带来额外时延。四类服务：①主机名 → IP；②主机别名 → 规范名及 IP；③邮件服务器别名；④负载分配（一个规范名对应一组 IP，轮转）。

例：www.baidu.com 可有多条 A 记录指向不同机房，轮转实现粗粒度均衡。

2.5.2 层次结构与本地域名服务器#

定义/结论：集中式 DNS 不可行——单点故障、容量过大、远距离时延高、维护难、无法扩展；故按三层组织：根（13 组）、顶级域 TLD（.com、.cn）、权威（机构自建或托管）。本地 DNS 不属于层次结构，只做代理与缓存。

机制解释：根给出 TLD 地址；TLD 给出该域权威服务器地址（NS + 其 IP）；权威保存本域主机的 A 记录及 MX/NS，通常一主多辅。本地 DNS 邻近用户，代客户向上查询并缓存，常缓存 TLD 地址，故很少访问根。

例：校园网主机的 DNS 地址由 DHCP 下发，所有解析先问它。

2.5.3 递归查询与迭代查询#

定义/结论：递归：被问的服务器代查并返回最终答案；迭代：只返回下一站该问谁。实际中主机→本地 DNS 递归，本地 DNS→层次结构迭代。

机制解释：递归把负载压在域名服务器上，层次越高越重，故根与 TLD 通常不做递归；迭代只"指路"，负载留给本地 DNS。

例（带步骤）：解析 www.amazon.com，缓存为空：

  1. 主机→本地 DNS 递归查询（1 个报文）；
  2. 本地→根迭代，得 .com TLD 地址（1）；
  3. 本地→TLD 迭代，得 amazon.com 权威地址（1）；
  4. 本地→权威迭代，得 IP（1）；
  5. 本地缓存并返回。共 4 个报文，有缓存则更少。

2.5.4 DNS 缓存#

定义/结论：服务器把响应中的映射缓存在本地，条目在 TTL 到期后丢弃；因此实际查询很少访问根。

机制解释：缓存降低时延、减少全网 DNS 流量、减轻根与 TLD 压力；代价是"尽力而为"——主机换 IP 后要等所有相关缓存过期，全网才能访问新地址。

例：本地 DNS 解析过 www.baidu.com，TTL 为 300 s，则 300 s 内全部命中。

2.5.5 资源记录（RR）#

定义/结论：DNS 存储的映射是资源记录，四元组 （Name, Value, Type, TTL），TTL 决定其从缓存删除的时间。

Type Name Value 用途
A 主机名 IPv4 地址 主机名→IP
NS 域（foo.com） 该域权威服务器主机名 指路
CNAME 别名 规范主机名 别名→真名
MX 域名 该域邮件服务器规范名 邮件路由

机制解释：权威服务器对自己管辖的主机名存 A；非权威服务器（如 TLD）存 NS 加上"NS 的 Value 那台机器的 A"（glue），以打破"不知道 IP 就无法问它"的循环依赖。

例：(example.com, dns1.example.com, NS)、(dns1.example.com, 212.212.212.1, A)、(www.example.com, server7.example.com, CNAME)、(example.com, mail.example.com, MX)。

2.5.6 DNS 报文格式#

定义/结论：报文只有查询与回答两种且格式相同；前 12 字节为首部区域，其后是问题、回答、权威、附加四区。

首部字段 长度 含义
标识符 16 bit 标识查询，回答复制同值供匹配
标志 16 bit 查询/回答、权威/非权威、期望递归、递归可用
问题数 / 回答 RR 数 各 16 bit 两区域条目数
权威 RR 数 / 附加 RR 数 各 16 bit 两区域条目数

机制解释：问题区域 = 名字 + 类型（A/MX/NS）；回答区域 = 对最初名字的 RR（可多条）；权威区域 = 其他权威服务器记录；附加区域 = 有帮助的额外记录，如 MX 回答附带邮件服务器的 A，省去再问一次。

例：查 www.networkutopia.com 的回答中，回答区域是 CNAME（www→star），附加区域是 A（star→212.212.212.3）。

2.5.7 注册资源记录#

定义/结论：新域名要能被全网解析，需注册并配置权威服务器。

机制解释（以 networkutopia.com 为例）：

  1. 向注册登记机构注册域名，提供主/辅权威服务器名字与 IP；
  2. 机构在 .com TLD 插入 (networkutopia.com, dns1.networkutopia.com, NS) 与 (dns1.networkutopia.com, 212.212.212.1, A)；
  3. 自建权威服务器，插入 (networkutopia.com, 212.212.212.2, A)、(networkutopia.com, mail.networkutopia.com, MX)、(mail.networkutopia.com, 212.212.212.3, A)。

例：配置后解析 www.networkutopia.com，先被 TLD 指到 dns1，再由它给最终 IP。

典型例题#

例 1（DNS 概念辨析，作业题①）#

题目：关于 DNS 的正确说法？(A) 层次结构含根、顶级域、权威、本地域名服务器 (B) 每次解析都从根开始 (C) 主机总是把查询发给本地域名服务器 (D) 本地域名服务器保存本地 ISP 的域名数据库

答案：C。

解析：(A) 错，层次结构只有根、TLD、权威，本地 DNS 不在其中；(B) 错，有缓存，多数查询不必问根；(C) 对，主机配置的 DNS 就是本地 DNS，也是递归查询的起点；(D) 错，本地 DNS 只有缓存条目，原始数据在权威服务器。

例 2（访问路径判断，作业题②）#

题目：从 USTC 校园网解析 www.baidu.com，哪个域名服务器绝对不会被访问？(A) 根 (B) .com TLD (C) 百度企业网的本地域名服务器 (D) USTC 本地域名服务器 (E) baidu.com 权威服务器

答案：C。

解析：D 必访问（解析入口）；B 必访问（给出权威地址）；E 必访问（最终答案只能由它给）；A 可能访问（未缓存 TLD 地址时），题目问"绝对"，故不选；C 是百度内部主机上网用的解析代理，外部解析链路为"USTC 本地 DNS → 根/TLD → 百度权威"，不会绕到它。

例 3（时延计算，作业题③）#

题目：网页含 8 个很小的图片对象，与页面在同一服务器；RTT 为 RTT₀，忽略传输时延，求四种情况耗时。

情况 计算 结果
(1) 非持久、无并发 2RTT₀+8×2RTT₀ 18RTT₀
(2) 非持久、5 并发 2RTT₀+⌈ 8/5⌉×2RTT₀ 6RTT₀
(3) 持久、无流水线 2RTT₀+8×1RTT₀ 10RTT₀
(4) 持久、流水线 2RTT₀+1RTT₀ 3RTT₀

解析（逐步）：

  1. 对象共 1+8=9 个（HTML 也是对象），须先取回 HTML 才能解析图片 URL，故 HTML 的 2RTT₀ 是公共前缀；
  2. (1) 每对象单建连接：9×2RTT₀=18RTT₀；
  3. (2) 8 图分 ⌈ 8/5⌉=2 批，每批 2RTT₀，共 2+4=6RTT₀；
  4. (3) 建连只付一次，8 图各 1RTT₀，共 10RTT₀；
  5. (4) 8 个请求一次发出、响应 1 RTT 到齐，共 3RTT₀。

结论：3<6<10<18，流水线持久连接收益最大。

例 4（资源记录与报文数，作业题④）#

题目：.com TLD 已有 (networkutopia.com, NS, dns1.networkutopia.com) 与 (dns1.networkutopia.com, A, 212.212.212.1)。www、ftp 均运行在规范名 star.networkutopia.com（212.212.212.3），邮件服务器规范名 moon.networkutopia.com（212.212.212.4）。

(1) 权威服务器上的记录：

Name Type Value
www.networkutopia.com CNAME star.networkutopia.com
ftp.networkutopia.com CNAME star.networkutopia.com
star.networkutopia.com A 212.212.212.3
networkutopia.com MX moon.networkutopia.com
moon.networkutopia.com A 212.212.212.4

解析：www、ftp 是别名、star 是规范名，故写 CNAME 指向 star，再为 star 写一条 A；邮件分两步，域的 MX 指向 moon，再给 moon 写 A。MX 的 Value 必须是规范主机名，不能写 IP 或别名。

(2) 本地 DNS 已缓存 .com TLD 的 IP、此前未访问该域权威服务器；客户递归、本地迭代。两类解析各需几个查询报文？

① 解析 www.networkutopia.com：2 个查询报文。

  1. 已缓存 TLD 地址，直接向 .com TLD 迭代查询该名字的 A；
  2. TLD 不权威，回指路：NS（networkutopia.com→dns1）+ glue A（dns1→212.212.212.1）；
  3. 本地向 dns1 查询；
  4. dns1 回 CNAME（www→star）并在附加区域附 A（star→212.212.212.3），一次答全；
  5. 本地缓存并返回。共 2 个；若算上主机→本地的递归查询为 3 个。

② 为向 bob@networkutopia.com 投递，需 MX 与 moon 的 A：2 个查询报文。

  1. 向 TLD 查 networkutopia.com 的 MX（TLD 不存 MX，只回 NS + glue）；
  2. 向 dns1 查 MX，回 (networkutopia.com, moon.networkutopia.com, MX)，附加区域含 (moon, 212.212.212.4, A)；
  3. 本地把 IP 交给邮件服务器，据此建 SMTP 连接。共 2 个。

讨论：若第 ① 步已缓存该域 NS 与 glue，第 ② 步可直接问 dns1，只发 1 个；若权威只回 CNAME 不带附加 A，则要多查一次。

例 5（代理缓存 + 流水线持久 HTTP，作业题⑤）#

题目：网页含 n 张图片，HTML 传输时延可忽略；图片大小 L、传输时延不可忽略。机构网到源服务器往返时间 T、带宽 R，内部时延忽略，用流水线持久 HTTP。若除 HTML 外所有对象都在代理缓存且最新，求用时。

答案：t≈ 2T+nL/R。

解析（逐步）：

  1. HTML 不在缓存，代理须回源：建连 1 个 RTT（T）+ 请求/响应 1 个 RTT（T）= 2T；
  2. n 张图片全命中且新鲜：不回源、不发条件 GET，不消耗 T；
  3. 流水线持久：客户端到代理的建连与请求往返均在内部，时延忽略；
  4. 图片串行通过带宽 R 的链路，共 nL/R；
  5. 两段串行相加得 t=2T+nL/R。

讨论：若 HTML 也在缓存且新鲜，则 t=nL/R；若只部分命中，未命中的 k 张各多付 2T。

常见题型与解题模板#

模板 1（取页面时延）：①数对象 N（含 HTML）；②判连接：非持久 2N、持久无流水线 N+1、持久流水线 3；③判并发，批数 ⌈ N/m⌉；④加传输时延 L/R（流水对象累加）；⑤写明忽略项。

模板 2（DNS 报文数）：①画链"主机→(递归)本地→(迭代)根→TLD→权威"；②逐级判断能否直接答：根给 TLD 地址、TLD 给 NS+glue、权威给 A/CNAME/MX；③一条响应可带多条 RR；④区分"本地发出的查询数"与"含递归的总报文数"。

模板 3（资源记录）：主机用 A、别名用 CNAME（值须为规范名）、委派用 NS、邮件用 MX（值须为规范主机名）；NS 所在域须有配套 A（glue）。

模板 4（缓存/条件 GET）：命中未过期直接返回（按局域网时延算）；可能陈旧则发条件 GET，304 用本地副本，200 则更新；只有跨广域网的报文才计 T。

模板 5（协议对比）：按"连接数/端口/方向(推拉)/状态/编码/报文组织/带内或带外"七维列表对照。

易错点与辨析#

易错点 错误认识 正确理解

每次问根 必须从根开始 有缓存，常连 TLD 都不必问
递归/迭代 只是叫法不同 递归由服务器代查（越高越重）；迭代只给下一站
非持久 RTT 每对象 1 个 RTT 每对象 2 个 RTT

Cookie 存哪 用户信息存客户端 信息在服务器数据库，客户端只存 ID

辨析一（HTTP vs FTP）：都用 TCP；HTTP 一条连接"带内"传控制与数据、无状态；FTP 两条连接"带外"、有状态、控制命令用 7 bit ASCII。

辨析二（SMTP vs HTTP）：都持久；SMTP 推、限 7 bit ASCII、所有对象一个报文；HTTP 主要拉、可传二进制、每对象一个响应。

3.1 传输层服务与复用/分解#

3.1.1 传输层与网络层的关系#

定义/结论：网络层提供主机到主机的逻辑通信，传输层提供进程到进程的逻辑通信，且只运行在端系统中。

机制：IP 只认目的主机，无法判断该交给哪个进程，传输层用端口号把"主机间交付"细化为"套接字间交付"。因此传输层服务受制于网络层的服务模型：IP 只做尽力而为交付（不保证交付、按序、完整），传输层就给出不了时延与带宽保证；但它能在 IP 之上增强出可靠按序交付（TCP），加密则由应用层的 TLS 完成。

例子：一台电脑边看视频边下载，IP 只把分组送到主机，交给哪个程序由端口号决定。

3.1.2 多路复用与多路分解#

定义/结论：发送端把多个套接字的数据分别加首部、封装成报文段交给网络层，叫多路复用；接收端按首部字段把数据交付到正确套接字，叫多路分解。

机制：需要两个条件——套接字有唯一标识，报文段含有指示目标套接字的字段，即 16 bit 的源端口号与目的端口号。分解时只看目的端口（UDP）或四元组（TCP），源端口主要用于回发报文。套接字是进程与网络之间的门户。

例子：网页（TCP 80/443）、DNS（UDP 53）、游戏三股数据从同一网卡进出，靠目的端口分解到三个套接字。

3.1.3 端口号与套接字标识#

定义/结论：端口号是 16 bit 无符号整数（0~65535）。UDP 套接字用 <目的 IP, 目的端口> 二元组标识，TCP 连接套接字用 <源 IP, 源端口, 目的 IP, 目的端口> 四元组标识。

范围 名称 典型值
0~1023 周知端口 HTTP 80、HTTPS 443、DNS 53、SMTP 25、FTP 21
1024~49151 登记端口 MySQL 3306、代理 8080
49152~65535 动态端口 客户端由操作系统临时分配

机制：服务器绑定周知端口，客户端用临时端口。UDP 服务器只需一个套接字就服务所有客户，因为分解只看目的二元组；TCP 服务器为每条连接建一个套接字，因为四元组不同即不同连接——这就是"连接套接字与进程并非一一对应"，高性能 Web 服务器常单进程多线程。

例子：A（IP1:50001）与 B（IP2:50002）同时访问 S（IP3:80），UDP 服务器一个套接字全收，TCP 服务器建两个连接套接字。

3.2 UDP：无连接传输#

3.2.1 定位与适用场景#

定义/结论：UDP 是无连接、不可靠的传输协议，只提供进程间交付与差错检查，无可靠传输、流量控制、拥塞控制。

机制：发送前无握手，每段独立处理，无连接状态因而无需缓存、序号与拥塞参数。用它的四条理由：应用层控制更精细（可绕过拥塞控制、自行实现可靠性）；无需建链，省一个 RTT；无状态可支撑更多并发；首部仅 8 B。

例子：DNS 一次查询-响应只用一个 RTT，建 TCP 反而时延翻倍；流媒体、SNMP、RIP 同理。但 UDP 无拥塞控制，大量使用会挤占 TCP 流量。

3.2.2 报文段结构#

定义/结论：UDP 首部固定 8 B，含 4 个 16 bit 字段，其后为数据。

字段 作用
源端口号 供对方回发，分解时不用
目的端口号 分解的唯一依据
长度 报文段总长（首部+数据），最小 8
校验和 覆盖伪首部+首部+数据；全 0 表示未计算

机制：长度字段把边界显式写在首部，故 UDP 面向报文，接收方一次交付一个完整报文。校验和在 IPv4 可选、IPv6 强制。无序号字段，因而无法判乱序、无法去重。

例子：应用数据 12 B 时长度字段为 8+12=20，即 0x0014。

3.2.3 校验和的计算#

定义/结论：发送端把"伪首部 + 首部 + 数据"视作 16 bit 整数序列反码求和（进位回卷），取反后写入；接收端连同校验和一起求和，结果全 1 判无错，出现 0 位则一定有错。

机制：计算前先把校验和字段置 0。伪首部 12 B——32 bit 源 IP、32 bit 目的 IP、8 bit 全 0、8 bit 协议号 17、16 bit UDP 长度；它不传输，作用是把 IP 地址拉进校验范围，否则目的 IP 被改错也可能通过。16 bit 校验和有漏检概率，"全 1"只说明很可能没错，且只能检错不能纠错；发现出错只能丢弃或交应用并警告。

例子：完整手算见例 1，校验和为 0x2778，验证 0xD887+0x2778=0xFFFF。

3.2.4 链路层已有校验，为何 UDP 还要校验#

定义/结论：这是端到端原则——逐跳校验保护链路，端到端校验保护数据。

机制：不保证路径上每条链路都做校验；链路层只在每跳收发端口校验，分组在路由器内存中仍可能翻转比特；只有端到端校验才保证应用看到的数据正确。

例子：分组过 5 台路由器，每跳校验都通过，但第 3 台内存故障翻转 1 bit，只有端到端校验和能发现。

3.3 可靠数据传输原理#

3.3.1 服务抽象与设计套路#

定义/结论：把"可能出错、可能丢包"的信道抽象成"不损坏、不丢失、按序到达"的信道，向上 rdt_send()，向下 udt_send()，接收侧 rdt_rcv() 触发、deliver_data() 交付。

机制：固定套路——列出出错类型（比特错、丢包）；决定如何发现（校验和、定时器）；决定如何恢复（重传）；分析重传引出的新问题（反馈受损、冗余分组）；用序号解决；画时间线图；归纳成 FSM。

例子：TCP 的校验和、ACK、序号、定时器、重传都能在 rdt 家族找到原型。

3.3.2 rdt1.0 与 rdt2.0：从完全可靠到比特错#

定义/结论：rdt1.0 假设信道完全可靠；rdt2.0 假设只可能比特错，需检错 + 反馈 + 重传，这类协议统称 ARQ。

机制：rdt1.0 收发都是单状态，收到就发、收到就交。rdt2.0 接收方检错后回 ACK 或 NAK，发送方收到 ACK 才发下一段、收到 NAK 就重传，发一个等一个的方式叫停等。三种新机制：接收方检错、接收方反馈、发送方重传。

              rdt_send(data) / 组包 sndpkt, udt_send(sndpkt)
    +-------------------------------------------------------------+
    |                                                             |
    v                                                             |
+-----------------+                              +-----------------+
|     状态 1      |                              |     状态 2      |
|  等待上层调用    | ---------------------------> |  等待 ACK/NAK   |
+-----------------+                              +-----------------+
    ^                                                  |     ^
    |   rcv ACK / (无动作)                              |     |
    +--------------------------------------------------+     |
                                                             |
         rcv NAK 或 校验错 / 重传 sndpkt  -------------------+

例子：ACK 在回程被打成乱码时发送方只能重传，接收方收到两份相同数据——rdt2.0 的致命缺陷就是没考虑反馈本身受损。

3.3.3 rdt2.1 与 rdt2.2：用序号治重复#

定义/结论：加 1 bit 序号（0/1）即可解决反馈受损导致的重复分组；2.2 进一步取消 NAK，只用带序号的 ACK。

机制：2.1 中发送方拆成两个序号状态，收到 NAK 或出错反馈就重传，收到期望序号的 ACK 才切换；接收方对重复分组回 ACK 但不交付、不变状态。2.2 中接收方只对正确接收的分组回 ACK 并带上其序号，出错时重发上一个 ACK；发送方收到期望 ACK 才前进，收到冗余 ACK 就重传。停等时同一时刻只有一段在途，1 bit 序号足够。

例子：ACK0 丢失后发送方重传 pkt0，接收方发现序号 0 已收过，重发 ACK0 但不再向上交付。

3.3.4 rdt3.0：用定时器治丢包#

定义/结论：信道既可能比特错也可能丢包，在 2.2 上加定时器即 rdt3.0，也称比特交替协议。

机制：发完启动定时器；收到期望序号的 ACK 则停表并切换状态；超时则重传并重启定时器；收到非期望 ACK 不处理，等超时。接收方 FSM 与 2.2 完全相同——ACK 丢失对接收方不可见，只需按序号判重。

例子：数据丢失、ACK 丢失、过早超时三种情形都靠"序号 + 定时器"自愈：超时重传，接收方按序号识别重复并重发 ACK。

3.4 流水线协议：GBN 与 SR#

3.4.1 停等效率与流水线#

定义/结论：停等协议发送方利用率 U=(L/R)/(RTT+L/R)，远小于 1，因为绝大部分时间在等 ACK。

机制：分子是推比特上链路的时间，分母是发出到收到确认的整个周期。要让利用率上去必须让链路上同时有多段在途，即流水线，它要求扩大序号范围、缓存多个分组。差错恢复有两条路线：GBN 与 SR。流水线利用率 U=(N· L/R)/(RTT+L/R)，上限 1。

例子：L=8000 bit、R=1 Mb/s、RTT=30 ms 时 U=8/38≈21%；取 N=10 理论上达 2.1，说明链路已被填满，实际 100%。

3.4.2 回退 N 步（GBN）#

定义/结论：GBN 允许连发多段而不等确认，但已发送未确认数不超过 N；接收方只按序接收，失序一律丢弃，采用累积确认。

机制：base 为最早未确认序号、nextseqnum 为下一个待发序号，序号空间分四段：已确认、已发未确认、可发未发、不可用，窗口随 ACK 滑动。发送方只对最早的未确认段设一个定时器，超时重传窗口内全部已发未确认段；收到 q≥ base 的 ACK 令 base=q+1，旧 ACK 忽略。接收方只接受序号等于 expectedseqnum 的段。序号空间 k 时要求 N≤ 2ᵏ-1，留一个序号区分新旧分组。

例子：见例 2 推演。优点是接收缓存简单；缺点是失序段被丢弃、浪费带宽，一次丢包常引发一批重传。

3.4.3 选择重传（SR）#

定义/结论：SR 只重传未收到 ACK 的段，接收方逐包确认并缓存失序段，缺口补齐后一起按序交付。

机制：发送方为每段各设一个定时器，收到窗口内 ACK 就标记已确认，若恰为 send_base 则窗口滑到最小未确认处。接收方对窗口内到达的段一律回 ACK，失序则缓存；对 [rcv_base-N,rcv_base-1] 内的重复段也必须回 ACK，否则 ACK 丢失后发送方窗口无法前进。两难困境：窗口过大会让接收方分不清新段与旧段重传，故 N≤ 2ᵏ⁻¹，即不超过序号空间一半。代价是多定时器与大量缓存。

例子：见例 3 与 GBN 在同一丢包场景下的对比。

3.5 TCP 概述与报文段结构#

3.5.1 TCP 的连接特性#

定义/结论：TCP 是面向连接、全双工、点对点的可靠字节流服务，并提供流量控制与拥塞控制。

机制：数据前先三次握手建立参数与状态；双向可同时传；一条连接只有一收一发；把数据视为无结构字节流，不保留报文边界；靠窗口一次发多段；连接状态只在两端主机，路由器不感知。MSS 是应用数据的最大长度，不含首部：以太网 MTU=1500 B 减 20 B IP 与 20 B TCP 首部，得 1460 B。

例子：一次 write() 写 3000 B，TCP 可能切成 1460+1460+80 三段，接收方 read() 的边界与写入无关。

3.5.2 报文段结构#

定义/结论：TCP 报文段由首部与数据组成，首部最短 20 B、最长 60 B。

字段 长度 作用
源/目的端口 各 16 bit 复用与分解
序号 seq 32 bit 数据首字节的字节流编号
确认号 ack 32 bit 期望收到的下一个字节序号
首部长度 4 bit 以 32 bit 为单位，最小 5
保留 / 标志位 6 + 6 bit 标志：URG、ACK、PSH、RST、SYN、FIN
接收窗口 rwnd 16 bit 流量控制，通告可用缓存
校验和 16 bit 覆盖首部与数据
紧急指针 16 bit 指向紧急数据末尾
选项 变长 MSS、窗口扩大因子、SACK、时间戳

机制：4 bit 首部长度 + 6 bit 保留 + 6 bit 标志恰凑成一个 16 bit 字，这就是"一行 4 字节"的来源。rwnd 仅 16 bit，最大 65535 B，高速网络须用窗口扩大选项，实际窗口 =rwnd×2ˢʰⁱᶠᵗ。

例子：不带选项与数据的纯 ACK 段，首部 20 B，首部长度字段值为 5。

3.5.3 序号与确认号规则#

定义/结论：序号是字节编号而非报文段编号；确认号是"期望收到的下一个字节序号"，采用累积确认。

机制：若一段携带字节 x… x+L-1，则 seq=x，正确收到后回 ACK=x+L。SYN 与 FIN 各占一个序号，即使不带数据。初始序号随机，避免新旧连接数据混叠。辨析：GBN 的 ACK 是"已按序收到的最大序号"，TCP 的确认号是"期望的下一个字节序号"，两者差 1。

例子：ISN=215，发 100 B 后关闭：SYN 的 seq=215；数据 seq=216（占 216~315）；FIN 的 seq=316；服务器对 FIN 确认 317。

3.6 TCP 的可靠数据传输#

3.6.1 RTT 估计与超时#

定义/结论：超时值须略大于 RTT；TCP 用 SampleRTT 的指数加权移动平均加 4 倍偏差来估计。

机制：EstimatedRTT=(1-α)EstimatedRTT+α SampleRTT（α=0.125）；DevRTT=(1-β)DevRTT+β|SampleRTT-EstimatedRTT|（β=0.25）；TimeoutInterval=EstimatedRTT+4DevRTT。SampleRTT 只测"一次发送就成功"的段，因为重传后的 ACK 无法判断确认的是哪次发送（确认二义性），这就是 Karn 算法。超时后超时值加倍，直到收到新 ACK 再按公式重算。

例子：EstimatedRTT=100 ms、DevRTT=10 ms 时超时约 140 ms；超时一次后取 280 ms，再超时取 560 ms。

3.6.2 发送方的三个事件#

定义/结论：发送方只处理三类事件——收到上层数据、定时器超时、收到 ACK，且只对最早的未确认段维护一个定时器。

机制：收到数据则封装发送，定时器未运行则启动；超时重传最早的未确认段并重启；收到 ACK=y 时若 y>SendBase 则令 SendBase=y 并标记此前字节已确认，仍有未确认数据则重启定时器，否则停止。

例子：连发 5 段只丢第 2 段，后续段的确认号仍是 3，SendBase 停在 2，直到重传的 2 被确认才跳到 6。

3.6.3 快速重传#

定义/结论：超时等待太长，TCP 用"3 个冗余 ACK"作为丢包早期信号触发快速重传。

机制：冗余 ACK 是再次确认已被确认过的段的 ACK。接收方每收到失序段就重发最近一次按序确认的 ACK；发送方连收 3 个相同 ACK 即可断定该段丢失（IP 通常按序交付），立即重传 SendBase 处。

例子：发 1~6 而 2 丢失，收到 ACK1、ACK1、ACK1、ACK1，后 3 个是冗余，凑满 3 个即重传 2。

3.6.4 ACK 生成策略#

情形 接收方动作
按序到达，前一段尚未确认 最多推迟 500 ms，等下一段一起确认
按序到达，前一段正待确认 立即累积确认，一次确认两段
失序或重复到达 立即发冗余 ACK，通报缺口
部分/完全填充缺口且起于缺口低端 立即发 ACK

机制：推迟确认可减少 ACK 数量，但过久会造成不必要重传并使 RTT 估计失真，故设 500 ms 上限并规定至少每两段确认一次。全双工时 ACK 可捎带在反向数据段中。

例子：连续收到两个满 MSS 段，通常只回一个累积 ACK。

3.6.5 混合本质#

定义/结论：TCP 的差错恢复既非纯 GBN 也非纯 SR，而是两者混合。

机制：像 GBN——累积确认、单定时器、按序推进；像 SR——缓存失序段、只重传出错的那一段。启用 SACK 后接收方可报告非连续块边界，发送方精确重传，更接近纯 SR。

3.7 TCP 连接管理#

3.7.1 三次握手#

定义/结论：让双方都确认"对方存在、愿意连接、初始序号与参数已同步"。

  客户                                                 服务器
   |  SYN=1, seq=client_isn  （不带数据）                |
   | ------------------------------------------------>  | LISTEN -> SYN_RCVD
   |                                                    | 分配缓存与变量
   |  SYN=1, ACK=1, seq=server_isn, ack=client_isn+1    |
   | <------------------------------------------------  |
   |  ACK=1, seq=client_isn+1, ack=server_isn+1         |
   | ------------------------------------------------>  | -> ESTABLISHED
   |  （可携带数据）                                     |

机制：第一步客户端随机选 client_isn 并置 SYN=1；第二步服务器分配缓存与变量，回 SYN=1、ACK=1，确认 client_isn+1 并给出 server_isn；第三步客户端分配资源，确认 server_isn+1、序号 client_isn+1，此步可带数据，此后 SYN 均为 0。为什么不是两次：滞留在网络中的陈旧 SYNACK 会让服务器误认为连接已建立并分配资源，而客户端并不理会，形成半开连接；第三次 ACK 让服务器确认客户端收到了 SYNACK。

例子：客户端 ISN=215、服务器 ISN=500 时，三步的 (seq, ack) 为 (215, —)、(500, 216)、(216, 501)。

3.7.2 四次挥手#

定义/结论：TCP 全双工，两个方向须分别关闭，故通常四次，实际中第 2、3 次可合并为三次。

  客户                                                 服务器
   |  FIN=1, seq=x                                      |
   | ------------------------------------------------>  | -> CLOSE_WAIT
   |  ACK=1, ack=x+1                                    | 继续发剩余数据
   | <------------------------------------------------  |
   |  半关闭：不再发数据，但可继续接收                     |
   |  FIN=1, ACK=1, seq=y, ack=x+1                      |
   | <------------------------------------------------  | -> LAST_ACK
   |  ACK=1, ack=y+1                                    |
   | ------------------------------------------------>  | -> CLOSED
   |  TIME_WAIT，等 2MSL 后真正关闭                       |

机制：主动方发 FIN 后不再发新数据但仍可接收，收到 ACK 后进入 FIN_WAIT_2；被动方进入 CLOSE_WAIT，可把剩余数据发完再发自己的 FIN；主动方回最后 ACK 后进入 TIME_WAIT，等 2MSL 才释放资源。TIME_WAIT 的两个作用：保证最后 ACK 送达（丢失则对方重传 FIN，本方还能再回 ACK）；让旧报文段在网络中消亡，避免干扰同四元组的新连接。

例子：客户发 FIN(x)，服务器回 ACK(x+1)；服务器发完剩余数据发 FIN(y)，客户回 ACK(y+1)，再等 2MSL 关闭。

3.7.3 SYN 洪泛与 RST#

定义/结论：第二步服务器就要分配资源，这给 SYN 洪泛攻击留下缺口。

机制：攻击者发大量 SYN 不回第三步 ACK，服务器为每个半开连接保留资源 30~120 s，耗尽后无法服务正常用户。对策是 SYN Cookie：第二步不分配资源，把连接信息编码进 server_isn，收到第三步 ACK 再校验分配。目的端口无监听套接字时，服务器回 RST=1 拒绝。

例子：向未开放端口发起连接会立即收到 RST 而快速失败，而不是静默超时。

3.8 TCP 流量控制#

3.8.1 接收窗口 rwnd#

定义/结论：流量控制防止发送方淹没接收方缓存，用 rwnd 通告可用空间。

机制：设 LastByteRcvd 为已放入缓存的最后字节号、LastByteRead 为应用已读出的最后字节号，则 rwnd=RcvBuffer-(LastByteRcvd-LastByteRead)，发送方须满足 LastByteSent-LastByteAcked≤ rwnd。rwnd 随应用读取速度动态变化，反映接收方能力；cwnd 反映网络能力，实际窗口取 \mincwnd,rwnd。

例子：缓存 4000 B、已收 3000 B 未被读取，则 rwnd=1000 B，发送方最多再发 1000 B 未确认数据。

3.8.2 零窗口与持续探测#

定义/结论：rwnd=0 时发送方必须停发；若双方都静默，接收方缓存腾空后无法通知对方（没有数据可确认，也就无 ACK 可捎带），会死锁。

机制：发送方收到零窗口通告后启动持续计时器，超时发一个 1 字节的零窗口探测段；接收方在响应中通告当前 rwnd；若仍为 0 则重置计时器继续探测。

例子：接收方应用暂停读取导致 rwnd=0，发送方靠探测报文得知窗口恢复后立刻续传。

3.9 TCP 拥塞控制#

3.9.1 拥塞的原因与代价#

定义/结论：拥塞是"太多发送方太快发送太多数据、超出网络处理能力"，表现为丢包与长时延。

机制：代价有三——为达同样有效吞吐必须额外重传而浪费带宽；不必要的重传把同一分组的多个副本送进网络；被丢弃的分组已消耗的上游带宽全部作废。极端时出现"拥塞崩溃"：负载很高而吞吐很低。

例子：多条连接同时以接近链路容量的速率发送，队列溢出开始丢包，重传又把负载推高，形成正反馈。

3.9.2 两类方法#

方法 反馈来源 代表 特点
端到端 端系统观察丢包与延迟 TCP IP 无显式反馈，简单但滞后
网络辅助 路由器显式通知 ATM、TCP ECN 反应快，需设备支持

机制（ECN）：路由器在 IP 首部打标记，接收方在 ACK 中置 ECE 位，发送方把 cwnd 减半并在下一段置 CWR 位回应，从而在丢包前减速。

例子：数据中心启用 ECN 可显著减少丢包与重传，降低尾时延。

3.9.3 拥塞窗口与 AIMD#

定义/结论：LastByteSent-LastByteAcked≤\mincwnd,rwnd，发送速率约为 cwnd/RTT。

机制：AIMD——无丢包时每 RTT 把 cwnd 加 1 MSS，线性探测带宽；检测到丢包则减半，快速退出。这种锯齿行为使多条连接收敛到公平共享。

例子：cwnd=16 MSS、RTT=100 ms、MSS=1460 B 时速率约 16×1460/0.1≈234 KB/s。

3.9.4 慢启动与拥塞避免#

定义/结论：慢启动从零快速探明带宽，拥塞避免在阈值附近小心试探。

   慢启动(指数) 拥塞避免(线性) 乘性减后重新加性增

机制：慢启动时 cwnd 初值 1 MSS，每收到一个 ACK 加 1 MSS，等价每 RTT 翻倍；达到 ssthresh 转入拥塞避免，此后每收到一个 ACK 增加 MSS\timesMSS/cwnd，即一个 RTT 累计加 1 MSS。丢包时先把 ssthresh 设为 cwnd 的一半，再按 Tahoe/Reno 处理。"慢启动"其实是指数增长，只是起点低。

例子：ssthresh=8 MSS 时 cwnd 为 1、2、4、8，第 4 个 RTT 后转拥塞避免，继续 9、10、11……（见例 5）。

3.9.5 快速恢复：Tahoe 与 Reno#

事件 Tahoe Reno
超时 ssthresh=cwnd/2，cwnd=1，慢启动 同 Tahoe
3 个冗余 ACK ssthresh=cwnd/2，cwnd=1，慢启动 ssthresh=cwnd/2，cwnd=ssthresh+3，快速恢复
快速恢复中再收冗余 ACK — cwnd 加 1 MSS
快速恢复中收到新 ACK — cwnd=ssthresh，转拥塞避免
快速恢复中超时 — ssthresh=cwnd/2，cwnd=1，回慢启动

机制：收到冗余 ACK 说明网络仍在传送数据（后续段已到达），只是丢了一段，不必推倒重来，只需窗口减半再放大，让发送方在缺口填补期间继续发包；加 3 是因为已有 3 段离开网络进入接收缓存。

例子：cwnd=20 MSS 时收 3 个冗余 ACK，Reno 令 ssthresh=10、cwnd=13 进入快速恢复；收到新 ACK 后 cwnd=10 转拥塞避免。

3.9.6 公平性#

定义/结论：K 条 TCP 连接共享带宽 R 的瓶颈链路时，理想情况各得 R/K。

机制：加性增沿 45° 线增长、乘性减按比例收缩，反复迭代后收敛到等分线附近。三个例外：RTT 不同不公平（RTT 小者增长快）；MSS 不同不公平；应用可开多条并行连接，连接多者分得多。UDP 不受约束，会挤压 TCP。

例子：链路上已有 9 条连接，新应用开 1 条得 R/10；若开 11 条则拿到 11R/20=R/2。

3.9.7 吞吐量估算#

定义/结论：忽略慢启动，平均吞吐约为 0.75W/RTT，W 为丢包时的窗口。

机制：丢包时速率 W/RTT，丢包后减半为 W/2RTT，窗口在两极值间线性往复，平均窗口 0.75W。计入丢包率 L 时 Mathis 公式为 吞吐=1.22· MSS/RTT·√(L)。吞吐与 RTT、丢包率成反比，长肥管道上传统 TCP 效率很低，故需 CUBIC、BBR。

例子：MSS=1460 B、RTT=100 ms、L=0.01 时吞吐约 1.22×1460/(0.1×0.1)≈178 KB/s。

例 1（UDP 校验和手算）#

源 IP 192.168.1.100、目的 IP 192.168.1.1、协议 17、UDP 长 20 B、源端口 12345、目的端口 53，数据 12 B，16 bit 字依次为 0x0102、0x0304、0x0506、0x0708、0x090A、0x0B0C。求校验和。

# 来源 字

5~6 伪首部：全 0+协议 17、长度 0x0011、0x0014

例 2（GBN 窗口推演）#

序号空间 k=3（0~7），窗口 N=4，pkt2 首次丢失，其余不丢不乱序。

步骤 事件 base/next 发送方 期望号 接收方
1 窗口空 0/0 发 0~3，为 0 启定时器 0 —
2 pkt0 到 0/4 — 1 交付 0，ACK0
3 ACK0 到 1/4 base=1，发 4 1 —
4 pkt1 到 1/5 — 2 交付 1，ACK1
5 ACK1 到 2/5 base=2，发 5 2 —
6 pkt2 丢失 2/6 定时器继续计时 2 —

8 冗余 ACK1 2/6 忽略（q<base） 2 —

10 pkt2 超时 2/6 重传 2、3、4、5 2 —
11 重传 2~5 到 2/6 — 6 依次交付，ACK2~ACK5

统计：6 个有效分组，首发 6 次 + 重传 4 次 = 10 次，冗余 4 次，效率 60%。结论：GBN 单定时器、接收方不缓存，实现极简；但一次丢包会让其后所有已发段全部重传。

例 4（TCP 序号与确认号）#

（1） ISN=215，发一个 100 B 段后关闭。解：SYN 占一个序号，seq=215；数据占 216~315，seq=216；FIN 占一个序号，seq=316。服务器确认号依次为 216、316、317。

（2） A 发三个各 1000 B 的段，seq=1000、2000、3000，B 只收到第 1、3 个。解：收到 seq=1000 回 ACK=2000；收到 seq=3000 发现缺口，仍回 ACK=2000 并缓存。A 收到第 3 个冗余 ACK 后快速重传 seq=2000，不等超时。

（3） 两段 seq 为 80、120，第一段多长？若第一段丢失而第二段到达，确认号是多少？解：120-80=40 B；期望仍为 80，故 ACK=80。

（4） 判断"A 已发送未确认的字节数不超过接收缓存大小"。解：正确，即 LastByteSent-LastByteAcked≤ rwnd。

例 5（慢启动与拥塞窗口随 RTT 变化）#

MSS=1 KB，初始 cwnd=1 MSS，初始 ssthresh=8 MSS，应用始终有数据，rwnd 足够大。

RTT 阶段 cwnd/MSS 说明
1 慢启动 1 起点
2 慢启动 2 每 ACK +1 MSS，等价每 RTT 翻倍
3 慢启动 4 —
4 慢启动 8 达到 ssthresh，转拥塞避免
5~12 拥塞避免 9→16 每 RTT +1 MSS
— 超时 1 ssthresh=16/2=8，cwnd=1
13 慢启动 1 重新开始
14 慢启动 2 —
15 慢启动 4 —
16 慢启动 8 再次达到 ssthresh，转拥塞避免
17 拥塞避免 9 新一轮线性增长

结论：①超时前共发 1+2+4+8+9+…+16=115 MSS，约 115 KB；②超时前 cwnd=16 MSS，故 ssthresh=8；③若改为"3 个冗余 ACK"且用 Reno，则 cwnd=8+3=11 并进入快速恢复，不回落到 1；④ssthresh 越大慢启动越久，cwnd 呈 1、2、4、8、16…… 的指数序列。

易错点与辨析#

  1. 粒度：网络层主机到主机，传输层进程到进程；"IP 地址标识进程"是错的。
  2. 二元组与四元组：UDP 只看目的二元组，故一个套接字服务所有客户；TCP 四字段全匹配，故每连接一个套接字。
  3. UDP 不可靠 ≠ 无用：它提供差错检测，只是不做恢复。
  4. 校验和全 1 只是很可能没错：16 bit 有漏检概率，且只能检错不能纠错。
  5. 伪首部不传输：只参与计算，却把 IP 地址纳入校验范围。
  6. 停等与流水线：停等利用率与窗口无关；流水线才是 (NL/R)/(RTT+L/R)，分母不乘 N。
  7. 两种 ACK 差 1：GBN 的 ACK 是"已按序收到的最大序号"，TCP 的确认号是"期望的下一个字节序号"。
  8. GBN 窗口上限是 2ᵏ-1 而非 2ᵏ：须留一个序号区分新旧分组。
  9. SR 窗口上限是序号空间一半：否则新旧接收窗口重叠，重传会被误认为新分组；且对窗口前的重复段也必须回 ACK。
  10. TCP 序号是字节号：下一段 seq 不一定是 m+1。
  11. 确认号是"期望收到"：收到 seq=38、4 字节，确认号是 42；但若中间有缺口则可能停在缺口起点，故"必然为 42"不成立。
  12. rwnd 会变化：随应用读取速度动态变化，不是常量；流量控制保护接收方，拥塞控制保护网络。
  13. 零窗口不是死锁：靠持续计时器与探测报文打破僵局。
  14. TIME_WAIT 不多余：保证最后 ACK 送达并让旧报文段消亡。
  15. 慢启动并不"慢"：它是指数增长，只是起点为 1 MSS；Reno 遇三次冗余 ACK 也不是简单减半，而是 ssthresh=cwnd/2、cwnd=ssthresh+3。
  16. 0.75W/RTT 中的 W 是丢包时的窗口，不是平均窗口；平均传输次数 = 平均重传次数 + 1。

转发、路由选择与网络服务模型#

转发与路由选择#

结论：转发是分组在同一台路由器内从入链路移到出链路，纳秒级、本地功能；路由选择是网络范围内确定源到目的路径，毫秒级、由多台路由器运行协议协作完成。

机制：路由协议交互算出转发表并下发到输入端口，转发只须查表，因此可纯硬件实现——前者像画地图，后者像看路牌。

例子：A 经 R1→R2→R3 到 B，路径由路由选择决定，R1 内部"2 口进、3 口出"只花几纳秒；链路故障后协议需数百毫秒收敛，期间仍按旧表转发。

数据面与控制面#

结论：数据面按转发表搬运分组，本地、逐包；控制面负责选路，网络范围；有的模型另设管理面（配置、计费）。

比较项 数据面 控制面
范围 单台路由器内部 整个网络
时间尺度 纳秒级、线速 毫秒级、收敛
实现 硬件（ASIC/TCAM） 软件（协议进程）
功能 查表、交换、排队、调度 运行 OSPF/BGP、安装转发表

机制：传统路由器两者同处一机箱；SDN 把控制面抽到远程控制器，路由器只留数据面、通过 OpenFlow 接收流表，即控制面与数据面分离。

例子：48 个 10 Gb/s 端口在 64 B 分组下需每秒转发约 9.4×10⁷ 个分组，而控制面每秒只处理几十条更新。

网络服务模型#

结论：服务模型定义分组在收发端系统间的端到端特性，可能提供确保交付、时延上界、有序交付、最小带宽、抖动上界、安全等；因特网只提供尽力而为：不保证交付、时延、顺序、带宽。

机制：ATM 用 CBR、VBR、ABR、UBR 分级满足需求；因特网把复杂性推到端系统、核心保持简单，以换取可扩展性。

例子：语音要求时延小于 150 ms 且抖动小，ATM 可预留资源保证，因特网只能靠应用层缓冲与编码冗余。

虚电路网络与数据报网络#

网络层可提供有连接（虚电路）或无连接（数据报）服务。与传输层不同：网络层是主机到主机、在网络核心实现、不能同时提供两种；传输层是进程到进程、在网络边缘实现、TCP 与 UDP 可并存。

虚电路网络#

结论：传输前建链、传输后拆链；分组携带 VC 号而非目的地址，沿固定路径保序传输；每台路由器为连接维护状态；资源可分配（独享），故能提供可预期性能。建链本质是先选好路径，是否预留资源可选。

机制：一条虚电路 = 端到端路径 + 每段链路各一个 VC 号（仅本地有意义）+ 沿途表项（入端口，入 VC 号，出端口，出 VC 号）；分组到达后按"入端口 + 入 VC 号"查表、改写 VC 号再送出。

为什么每段链路的 VC 号不同#

结论：VC 号只在单条链路上有意义，逐跳改写，不要求全路径统一。

机制：①缩短首部——本地编号只需覆盖本链路连接数；②简化建链——各链路独立选号，不必端到端协商；③便于管理——换设备只改本地表项。代价是路由器必须维护并改写状态。

例子：一条链路复用 1000 条虚电路只需 10 位编号（2¹⁰=1024）；若全网统一，1 万条连接要 14 位以上且每次建链都要协商。即使不做号转换，路由器仍须保存"VC 号→出接口"的映射。

数据报网络#

结论：不建立连接，路由器不保存端到端状态，只按目的地址转发；转发表由路由算法确定，约 1~5 min 更新一次；同一对主机的分组可能走不同路径而乱序。因特网即此类型。

机制：用目的地址的前缀匹配表项，多条匹配取最长前缀。转发表本身就是转发状态，但它与连接无关、只随前缀数增长，这是可扩展的关键。

例子：A 连发三个分组给 B，因表项更新分别走不同路径，B 可能按 2、1、3 顺序收到，需传输层重排。

路由器的工作原理：匹配—动作#

核心抽象是匹配 + 动作：用首部字段匹配表项，命中后执行动作（转发、丢弃、改写、上送控制器）。路由器由输入端口、交换结构、输出端口、选路处理器四部分组成。

输入端口与查表#

结论：输入端口做三层处理——物理层收比特、链路层解帧、网络层查转发表定出口；交换结构忙时分组在此排队。

机制：转发表存在输入端口内存或 TCAM 中，查表不打扰处理器，且必须在一个分组的到达间隔内完成；基于目的地转发只匹配目的前缀，广义转发匹配任意字段。

例子：10 Gb/s 端口、1000 B 分组时到达间隔为 1000×8/10¹⁰=800 ns；若用软件逐包处理需几微秒，端口必然积压。

输出端口排队与 HOL 阻塞#

结论：输出端口依次做组装、排队、调度。多个输入同时打向同一输出、且交换结构快于输出链路时，输出队列不可避免增长。队头阻塞（HOL）却发生在输入端口：单个 FIFO 队列的队头分组因目的端口忙而卡住，连累后面本可去空闲端口的分组。

机制：交换结构速率为端口速率 N 倍时输入排队可消除，但成本上升；输出端竞争与结构快慢无关，队列以 (N-1)R 增长。队列过深会增大时延并触发重传，故队列不是越长越好。HOL 的解法是虚拟输出队列（VOQ）：每个输入端口为每个输出端口各设一队列。

例子：4 个 1 Gb/s 输入同时发往 1 个 1 Gb/s 输出，队列净增 3 Gb/s，持续 1 ms 突发需缓存约 375 KB。

丢弃、AQM 与调度#

结论：队列满时须决定丢谁——弃尾、优先级丢弃、随机丢弃；主动队列管理（AQM）则在拥塞征兆出现时就提前丢弃或标记。调度策略有 FIFO、优先级调度、轮询、加权公平排队（WFQ）。

机制：RED 维护平均队长 avg←(1-w)avg+w q，设门限 minₜₕ、maxₜₕ：低于下限不丢，其间按线性增长的概率 p 丢/标记，高于上限全丢，目的是让 TCP 在队列溢出前降速，避免批量丢包与全局同步（也可只做 ECN 标记）。WFQ 按权重 wᵢ 分配带宽，长期比例约为 wᵢ/Σⱼ wⱼ。

例子：minₜₕ=20、maxₜₕ=40（分组）时，avg=30 的丢弃概率约为最大值一半；三队列权重 1:2:3、总带宽 600 Mb/s，则长期各得约 100、200、300 Mb/s。

IPv4 分片与重组#

结论：MTU 是链路层帧能承载的最大数据字节数（以太网 1500 B，某些广域网 576 B）。数据报大于 MTU 时必须分片，途中可多次分片，但只在目的主机重组。

机制：分片沿用原首部，只改几处——标识不变；片偏移 = 该片数据在原始载荷中的位置 ÷ 8；MF=1 表示后面还有分片、末片 MF=0，DF=1 表示禁止分片（超 MTU 则丢弃并回 ICMP）；TTL 继续递减；检验和重算。因偏移以 8 B 为单位，非末片数据长度必须是 8 的倍数，故每片最大数据量 N_\max=⌊(MTU-H)/8⌋× 8。重组按（源 IP, 标识）归并，原始总长 L=offsetₗₐₛₜ× 8+lenₗₐₛₜ，需缓冲区与定时器，超时未齐则整包丢弃。

例子：MTU=1500、4000 B 数据报切成 1480+1480+1020，偏移为 0、185、370（见例 1）。分片增大开销、丢一片要重传整包，还可被用于 DoS，故 IPv6 取消路由器分片，改由源主机做路径 MTU 发现。

IPv4 编址：子网、掩码与 CIDR#

接口、地址与分类编址#

结论：网络接口是主机/路由器与链路的边界，每个接口一个 IP 地址；地址分网络号（标识物理网络）与主机号（标识该网络上的接口），同一物理网络上各接口网络号相同。

机制：网络号由 ICANN/ISP 分配以保证全局唯一，主机号由管理员分配。早期分类编址按首位定类别：A 类 0（8+24，126 个网络）、B 类 10（16+16）、C 类 110（24+8，每网 254 个接口）、D 类组播、E 类保留。

例子：一台笔记本有 192.168.1.10 与 10.0.0.5 两个地址、两个子网；只有 300 台主机的单位若申请 B 类，浪费率超过 99%，这正是 CIDR 的动因。

特殊地址与子网#

结论：主机号全 0 是网络地址、全 1 是定向广播地址，都不能分配给接口，故可用数减 2；255.255.255.255 是受限广播（仅作目的地址，DHCP 用）；0.0.0.0 表示本机（仅作源地址）；127.0.0.0/8 为回环地址。私有地址 10/8、172.16/12、192.168/16 可在内网使用，但不得在公网路由。

机制：子网是具有相同子网地址、不经路由器即可互达的一组接口；划分子网时主机号被拆成"子网号 + 主机号"。子网掩码网络部分为 1、主机部分为 0，子网地址 = IP 按位与掩码。注意子网地址 ≠ 子网号：前者含网络号与子网号，后者只是借用的那几位。路由器是子网边界，每个接口连一个子网。

例子：掩码 255.255.252.0（/22）时，172.16.4.1 与 172.16.7.255 同属 172.16.4.0/22，而 172.16.8.1 属另一子网；192.168.1.0/24 可分配 .1~.254 共 254 个。

CIDR 与地址块#

结论：CIDR 按需分配，写作 a.b.c.d/x，x 为前缀位数，块大小 2³²⁻ˣ；既提高利用率又支持路由聚合。它不是路由协议，而是地址空间的划分方式。

机制：块长度必须是 2 的幂，块内地址的前 32-\log₂ L 位必须相同；需要 2000 个地址就分配 2048 个（2¹¹），即 /21。

例子：194.24.0.0/21 覆盖 194.24.0.0~194.24.7.255 共 2048 个；需要 500 个地址应给 512 个（/23）。

转发表与最长前缀匹配#

结论：表项含目的前缀/掩码、下一跳、输出端口，分前缀表项、特定主机表项（/32）、缺省表项（0.0.0.0/0）三类；IP 逐跳选路，只记下一跳，多条匹配时取最长前缀。

机制：硬件用 TCAM 并行比较所有前缀；下一跳地址必须与输出端口在同一子网，否则送不到。

DHCP：即插即用的地址配置#

结论：DHCP 是应用层协议（基于 UDP），让主机自动获得 IP、掩码、默认网关、DNS 等配置；C/S 架构，子网内需有服务器或知道服务器地址的中继代理（通常是路由器）。

机制：四步交互，客户初始源地址 0.0.0.0、目的地址 255.255.255.255，服务器以广播回复（此时客户还不能被单播寻址）；服务器用 UDP 67、客户机用 UDP 68；地址按租期使用，可续租。

  │◀─ OFFER（候选地址 yiaddr）───│
  │── REQUEST（选定并回显）─────▶│
  │◀─ ACK（租期、掩码、网关、DNS）│

例子：笔记本接入校园网，ACK 携带 yiaddr=10.20.30.45、mask=255.255.255.0、router=10.20.30.1、dns=10.20.0.53。DHCP 只解决配置不解决移动性：换网后地址变了，已建 TCP 连接无法维持。

NAT：地址转换与端口复用#

结论：NAT 让一个（或少量）公有地址为大量内部主机提供对外通信，内部使用私有地址；既减少公有地址需求，又使内部节点对外不可见。

机制：外出分组把（源 IP，源端口）改为（NAT 公有 IP，新分配端口）并写入转换表；进入分组用（目的 IP，目的端口）查表改回原地址与端口。端口号 16 位，一个公有 IP 可支持约 2¹⁶=65536 个并发连接，这就是端口复用——两台内网主机即使用同一源端口 3345，也会被映射成 5001、5002 两个不同公有端口。

例子：两台内网主机都用 3345 端口访问同一网站，仅凭 IP 无法区分，NAT 分配不同公有端口 5001、5002，回程按目的端口分别送回（见例 4）。

争议：端口本是进程编址却用于主机编址；路由器本应只处理三层却要解析传输层；中途改写地址端口违反端到端原则；破坏 P2P——NAT 后的主机不能被外部主动连接，只能靠连接反转与中继服务器缓解，长远解法是 IPv6。

IPv6：更大的地址空间#

结论：IPv6 的动机是 IPv4 地址耗尽，同时简化首部、加快转发，并支持 QoS、组播、移动性与安全；地址 128 位，首部固定 40 B。

机制：选项改为扩展首部、长度固定；取消首部检验和（省去逐跳重算）；取消路由器分片（只允许源分片，配合路径 MTU 发现）；新增 20 位流标签标识同一流。字段为版本(4b)、流量类别(8b)、流标签(20b)、载荷长度(16b)、下一个首部(8b)、跳数限制(8b)、源/目的地址(各 128b)。

例子：IPv4 首部 20 B 有 12 个字段，IPv6 固定 40 B 只有 8 个且无检验和、无选项，每包处理指令更少。

过渡：双栈与隧道#

结论：IPv6 与 IPv4 不兼容（但与其上所有协议兼容），过渡靠双栈与隧道。

机制：双栈节点同时运行两套协议，发前查 DNS：返回 AAAA 用 IPv6，返回 A 用 IPv4。纯 IPv6 分组穿过 IPv4 区域时：报头转换（译成 IPv4 首部，部分字段丢失）或隧道（把 IPv6 数据报整体作为 IPv4 载荷，出口解封装，保留全部信息）。隧道中 IPv6 的跳数限制不被 IPv4 路由器递减。

例子：两站点经 IPv4 骨干互联，入口路由器用协议号 41 封装，骨干按 IPv4 转发，出口剥去外层，两端如同一段直连 IPv6 链路。

通用转发与 OpenFlow#

结论：通用转发把"按目的地址转发"推广为"用任意首部字段匹配 + 执行动作集合"；控制面下发流表，交换机只做匹配与执行，这就是 SDN 的数据面。

机制：流表项含匹配字段、优先级、计数器、动作、超时；匹配域可有入端口、源/目的 MAC、以太类型、VLAN ID、源/目的 IP、协议号、ToS、TCP/UDP 端口（1.0 版为 12 元组）；动作有转发到端口、泛洪、丢弃、改写字段、上送控制器、入队。

任意（通配） 上送控制器 未知分组交控制器

典型例题#

例 1：MTU=1500 B，对 4000 B 数据报分片#

题目：4000 B 的 IPv4 数据报（含 20 B 首部）经 MTU=1500 B 链路，DF=0，求各片长度、偏移与 MF。

步骤：

  1. 载荷 =4000-20=3980 B。
  2. 每片最大数据 =⌊(1500-20)/8⌋×8=185×8=1480 B。
  3. 切片：1480 + 1480 + 1020 = 3980 B。
  4. 偏移（单位 8 B）：0、1480/8=185、2960/8=370。
  5. MF：前两片 1、末片 0；总长 1500、1500、1040。
分片 数据长度 总长度 片偏移 MF
1 1480 1500 0 1
2 1480 1500 185 1
3 1020 1040 370 0

验证：370×8+1020=3980，非末片长度均为 8 的倍数；若 DF=1 则丢弃并回 ICMP"需要分片但 DF 置位"。

题目：192.168.10.0/24 划分 4 个等长子网，求掩码、子网地址、可用范围、广播地址。

  1. 借位：4=2²，前缀 24+2=26，掩码 255.255.255.192。
  2. 块大小 2³²⁻²⁶=64，边界为 .0、.64、.128、.192。
  3. 每子网可用 2⁶-2=62 个地址。

例 4：NAT 转换表推演#

题目：NAT 公网地址 138.76.29.7，内部 A=10.0.0.2、B=10.0.0.3 均用源端口 3345 访问 128.119.169.80:80，写转换表并说明回程。

  1. A 发出源 10.0.0.2:3345，目的 128.119.169.80:80。

  4. 回程目的 138.76.29.7:5001 → 10.0.0.2:3345；:5002 → 10.0.0.3:3345。

题目：200.23.16.0/24、.17.0/24、.18.0/24、.19.0/24 能否聚合？

易错点与辨析#

  1. 转发 ≠ 路由选择：问"怎么知道往哪转发"答查转发表，问"表从哪来"才答路由协议。
  2. 网络层连接 ≠ 传输层连接：前者主机到主机、核心实现、只能二选一；后者进程到进程、边缘实现、TCP/UDP 并存。
  3. VC 号逐跳不同是设计：缩短首部、简化建链；但"路由器保存连接状态"不能省。
  4. 输入排队 vs 输出排队：前者靠加速比 N 可消除；后者由多输入争用同一输出引起，不可消除。
  5. HOL 阻塞发生在输入端口（单一 FIFO 队列），解法是 VOQ，勿与输出排队混淆。
  6. AQM/RED 不是"满了才丢"：平均队长超过下限就按概率提前丢/标记。
  7. 分片只在目的主机重组，IPv6 连路由器分片都取消；偏移以 8 B 为单位，DF 与 MF 含义相反。
  8. 其他常错：子网地址 ≠ 子网号；DHCP 服务器 67、客户机 68；NAT 靠端口区分主机；隧道中 Hop Limit 不递减。

5.1 控制平面的两种实现#

5.1.1 传统：每路由器控制#

结论：每台路由器运行同一路由协议的独立实例，交换报文，各自算出本机转发表。

机制与例：交换的是链路状态、距离矢量这类原始信息，不是算好的表；单台故障只影响邻居。OSPF 域内 20 台路由器各跑 Dijkstra，因 LS 数据库相同，结果一致。

5.1.2 SDN：集中式控制#

结论：控制平面逻辑上集中到远程控制器，控制器算好流表下发，路由器只留控制代理（CA）执行。

机制与例：控制器经南向接口（OpenFlow）收集拓扑、下发流表，应用经北向接口调用控制器。数据中心可为"大象流"单独选路，不必改路由协议。

5.1.3 两种实现对比#

维度 传统（每路由器控制） SDN（集中式控制）
计算位置 每台路由器各算各的 控制器统一计算
全局视图 无，靠协议交换拼出 有，控制器掌握全网
可编程性 改行为要升级所有设备 应用层写程序即可
故障影响 单台故障只影响局部 控制器是单点，需冗余
代表 OSPF、BGP OpenFlow、ONOS

5.2 路由选择算法及其分类#

5.2.1 选路问题的定义#

结论：在带权图 G=(N,E) 上找源到目的代价最小的路径；度量可为时延、带宽、费用、拥塞等，彼此常矛盾。

机制与例：路径代价是各边代价之和，"最优"随度量而变。2 跳卫星链路（每跳 250 ms）与 4 跳光纤（每跳 2 ms），按跳数选前者，按时延选后者。

5.2.2 三种分类维度#

维度 类型 含义
信息范围 全局算法 有全网拓扑与全部代价，可集中计算（LS）
信息范围 局部算法 只知道邻居及到邻居的代价（DV）
变化方式 静态 / 动态 手工配置不变 / 随拓扑、流量自动更新
负载敏感度 敏感 / 迟钝 代价是否反映拥塞；RIP、OSPF 默认迟钝

机制与例：全局算法要"先有地图"，代价是洪泛；局部算法不要地图，代价是收敛慢。RIP 把拥塞的 100 Mbps 链路和空闲的 2 Mbps 链路都算 1 跳，典型负载迟钝。

5.3 链路状态算法与 Dijkstra#

5.3.1 LS 的五个步骤#

结论：每个节点先洪泛拿到全网拓扑，再用 Dijkstra 算以自己为根的最短路径树。

机制与例：①发现邻居；②测链路代价；③构造 LS 分组（邻居 + 代价，带序号）；④泛洪全网；⑤各节点用同一拓扑独立计算。新接一条链路时两端各发新分组（序号 +1），全网重算。

5.3.2 Dijkstra 算法#

结论：按"当前距离最小"逐个确定节点，确定后不再改；要求边权非负。朴素 O(n²)，优先队列 O((n+E)\log n)，LS 洪泛需 O(nE) 条消息。

Dijkstra(G, s):
  N' = {s}
  for each v:
      相邻: D(v)=c(s,v), p(v)=s
      否则: D(v)=∞
  while N' ≠ N:
      w = 不在 N' 中且 D(w) 最小的节点
      N' = N' ∪ {w}
      for each v ∉ N' 且与 w 相邻:
          if D(w)+c(w,v) < D(v):
              D(v)=D(w)+c(w,v); p(v)=w
  返回 D 与 p

机制与例：边权非负时绕道不会更短，故 D(w) 立即定型，这是贪心正确性。转发表只存下一跳。链状 s-a-b-t（代价均 1）依次定出 a,b,t。

5.3.3 选路震荡#

结论：若链路代价随流量变化，所有路由器同时重算，会把流量整体甩来甩去。

机制与例：代价依赖流量 → 路由变 → 流量分布变 → 代价再变，正反馈叠加"同时运行"的自同步。A、B 两条路初始都走 A，A 压满后全改走 B，B 压满后又改回 A。解决办法：让代价不依赖流量，或随机化通告时间。

5.4 距离向量算法与 Bellman-Ford#

5.4.1 Bellman-Ford 方程#

结论：dₓ(y)=\minᵥc(x,v)+dᵥ(y)，v∈ N(x)——先走到某个邻居，再从其最优地走到 y。

机制与例：最优路径的后缀仍最优。c(x,y)=2、c(x,z)=7、d_y(z)=1，则 dₓ(z)=\min2+1,7+0=3，经 y。

5.4.2 四个关键词#

结论：DV 是分布式、迭代、异步、自我终止的算法。

机制与例：触发计算的事件只有两个——本地链路代价变化、收到邻居矢量。用 Dₓ(y)=\minᵥc(x,v)+Dᵥ(y) 更新，仅当自己的矢量变化才通告邻居，不可达置 ∞。

5.4.3 好消息快，坏消息慢#

结论：代价下降传播快，一轮一跳；代价上升或断链传播很慢，会形成环路与无穷计数。

机制与例：根因是"邻居把经过你的旧路由再告诉你"。A—B—C 链路上 A—B 断开后，B 从 C 处听说"到 A 只要 2"，算出 3；C 又据 3 算出 4，数字越滚越大（例 5-3）。

5.4.4 无穷计数与解药#

结论：根因是相互依赖的过时信息。对策：水平分割、毒性逆转、触发更新，再用有限值代表无穷（RIP 取 16）。

机制与例：水平分割——从邻居学的路由不再通告回它；毒性逆转——干脆通告 ∞；触发更新——变化立即发。例 5-3 中 C 到 A 的下一跳是 B，水平分割使 C 不向 B 通告该路由，B 立即置 16。

局限：两节点互指的环路可破，三节点以上（A 经 B、B 经 C、C 经 A）仍会计数到无穷。

5.5 LS 与 DV 的对比#

维度 LS（链路状态） DV（距离矢量）
信息范围 全网拓扑，洪泛给所有节点 只有邻居的矢量
报文开销 O(nE) 条消息 仅变化时发给邻居
收敛 O(n²) 计算，可能震荡 快慢不定，可能环路、计数到无穷
健壮性 只信自己测的代价，错误不扩散 "道听途说"，错误会扩散
典型协议 OSPF RIP

机制：LS 发原始测量值，人人独立算，一台路由器撒谎只污染自己的树；DV 发算好的结果，一家报错、邻居照用，错误像病毒扩散。

例：某路由器把代价 1 谎报成 100。LS 中别人仍用自己的 1，只有它自己变差；DV 中错误随矢量传开，可能造成全网绕路。

5.6 自治系统与域内/域间路由#

5.6.1 为什么要分层#

结论：扁平结构不可扩展——路由表爆炸、全网交换选路信息足以瘫痪网络；且每个网络想掌控内部路由。AS 同时解决"规模"与"自治"。

机制与例：AS 内部交换详细路由，对外只通告聚合前缀。校园网作为一个 AS，对外只向两个 ISP 通告一条前缀，外界不必知道校内有几百个子网。

5.6.2 AS、网关路由器与两类协议#

结论：AS 是同一管理控制下的一组路由器，有全局唯一 AS 编号（ICANN 分配）；AS 内跑相同的域内协议，AS 间跑相同的域间协议（BGP4）。

机制与例：网关路由器位于边界，同时跑域内与域间路由；转发表由两部分拼成。1a 由域间路由知道"从 1b 出去可达"，由域内路由知道"到 1b 走 1c→1b"。

协议 类别 算法 度量 封装
RIP 域内 IGP 距离矢量 跳数 UDP 520
OSPF 域内 IGP 链路状态 链路代价 直接封装 IP，协议号 89
BGP 域间 EGP 路径矢量 策略 + AS-PATH TCP 179

5.7 RIP：距离矢量做域内路由#

5.7.1 距离就是跳数#

结论：RIP 用跳数做距离，每段链路计 1；最多 15 跳，16 表示不可达，故 AS 直径不超过 15。

机制与例：跳数与带宽、时延无关，收到通告把距离加 1 即可，简单但把"近"当成了"快"。1 跳的 2 Mbps 链路会胜过 3 跳的千兆链路。

5.7.2 30 秒通告，180 秒失效#

结论：相邻路由器约每 30 秒交换一次响应报文（通告），封装在 UDP 中、端口 520，每报文最多 25 个子网；180 秒收不到就判失效。

机制与例：收到通告按 Bellman-Ford 更新，下一跳记为发来通告的邻居；失效时把经该邻居的路由置 16 并通知他人。30×6=180 秒，丢 5 个通告仍可容忍。

5.7.3 优缺点#

结论：优点是简单、开销小，适合小网；缺点是不分区、受 15 跳限制、度量单一、不支持等代价多路径、收敛慢。

机制与例：五六个分支的小企业网用 RIP 足够；大型 ISP 用 RIP，直径与收敛速度都无法接受。

5.8 OSPF：链路状态做域内路由#

5.8.1 链路状态与泛洪#

结论：OSPF 是链路状态协议，路由器向整个 AS（或所在区域）泛洪链路状态通告（LSA），人人掌握拓扑并各自跑 Dijkstra。

机制与例：LSA 描述"我连了谁、代价多少"，带序号防旧。R2—R5 断开，两端各发新 LSA，全网把该边代价改为 ∞ 后绕行。

5.8.2 报文与封装#

结论：OSPF 报文直接封装在 IP 数据报中，协议号 89，不用 TCP 或 UDP；共 5 种分组，一般至少每 30 分钟周期通告一次。

机制与例：5 种分组为 Hello、DD、LSR、LSU、LSAck，可靠性自己确认重传。抓包看到 IP 头 protocol=89 即 OSPF，UDP 520 则是 RIP。

5.8.3 分层：区域与骨干#

结论：一个 OSPF AS 可划分多个区域，区域内链路状态只在本区泛洪；所有区域必须连到骨干区域（区域 0），跨区流量经骨干转发。

               区域 0（骨干）
       R3(ABR) ------ R4 ------ R5(ABR)
          |                        |
     -----+-----              -----+-----
     |          |              |         |
    R1         R2             R6        R7
       区域 1                      区域 2

机制与例：区域边界路由器（ABR）把本区信息汇总成"子网 + 代价"通告其它区域，泛洪范围与 LSDB 规模都缩小。R1 访问 R6：R1→R3→骨干→R5→R6。

5.8.4 角色、优点与代价#

结论：路由器分内部路由器、骨干路由器、ABR、ASBR 四种。优点是认证、等代价多路径、多种 TOS 度量、支持多播（MOSPF）、可分层；缺点是泛洪开销大。

机制与例：OSPF 消息都经认证（简单口令或 MD5），防注入假 LSA；同一目的可多条等代价路径同时用。三条等代价链路时 OSPF 分摊流量，RIP 只选一条。

5.9 BGP：路径矢量做域间路由#

5.9.1 为什么域间不用最短路#

结论：域间目标是"能找到且符合策略"，不是"最优"；规模巨大、各 AS 度量不同、彼此未必信任，AS 也可能不愿替人转发。

机制与例：没有统一代价，商业关系（客户—提供商—对等）决定谁能走谁。到同一目标，经客户 AS 的 3 跳路径常胜经对等 AS 的 1 跳路径——替对等方转发是亏本的。

5.9.2 eBGP 与 iBGP#

结论：eBGP 连接相邻 AS 的网关，获取子网可达信息；iBGP 在 AS 内部各路由器间分发这些外部信息。

机制与例：BGP 对等方建立半永久 TCP 连接（端口 179），运行 BGP 的路由器称 BGP speaker。iBGP 不跨 AS、不改 AS-PATH，NEXT-HOP 常是外部地址，靠域内 IGP 到达。

5.9.3 路径矢量：前缀 + 属性#

结论：BGP 通告的路由 = 目的前缀 + 属性；最重要的是 AS-PATH（经过的 AS 列表）与 NEXT-HOP（下一跳 IP）。

机制与例：AS-PATH 兼作防环——含本 AS 号即丢弃；越短通常越优先，但只是启发式。"AS2 AS3"（2）胜过 "AS4 AS5 AS3"（3）。

5.9.4 选路顺序与热土豆#

结论：按"本地偏好（策略）→ 最短 AS-PATH → 最近 NEXT-HOP（热土豆）→ BGP 标识符"逐级比较，分出胜负即停。

机制与例：本地偏好数值大者优先；AS-PATH 短者优先；仍相同则比到各 NEXT-HOP 的域内 IGP 代价，选最近出口——热土豆，尽快甩出自己的 AS，可能选中出口链路更差的网关。

5.10 SDN 与 OpenFlow#

5.10.1 体系结构#

结论：SDN 分三层——基础设施层（交换机与流表）、控制层（控制器，即网络操作系统）、应用层（路由、流量工程等）。

机制与例：控制器经南向接口（OpenFlow）配置交换机、收集状态，应用经北向接口调用控制器。写一个"避开拥塞"的应用：读利用率 → 算新路径 → 下发流表。

5.10.2 OpenFlow 流表#

结论：流表项 = 匹配字段 + 动作 + 优先级 + 计数器；交换机"匹配—动作"，匹配不到就送控制器（Packet-In）。

优先级  匹配字段                                  动作
100    in_port=1, ipv4_dst=10.0.0.5/32        output:3
90     in_port=2, ip_proto=17, udp_dst=5001   drop
1      *（默认）                                controller

机制与例：控制器用 Flow-Mod 增删表项，交换机线速匹配、命中即执行（转发、丢弃、改字段、送控制器）。为视频流预留路径，沿途各写一条"匹配五元组 → 指定出端口"即可。

5.10.3 优势与挑战#

结论：优势是全局视图、可编程、流量工程容易、新功能上线快；挑战是控制器单点与扩展性、控制器与交换机状态一致性。

机制与例：传统网络要做避开拥塞的流量工程只能调 OSPF 权值、影响全网；SDN 只改特定流的路径。

5.11 ICMP：控制平面的听诊器#

5.11.1 报文与封装#

结论：ICMP 传递网络层的差错与询问信息，报文含类型、代码和出错 IP 数据报前 8 字节，封装在 IP 中（协议号 1）。

机制与例：差错报告单方向源节点发送、不必响应；对 ICMP 差错报文本身、非首片、多播地址不再报错。收到 TTL 为 1 的分组，丢弃并回类型 11、代码 0 的超时报文。

5.11.2 常见类型#

类型 名称 用途
0 / 8 回声应答 / 请求 ping 往返探测
3 目的不可达 网络/主机/端口不可达
4 源抑制 早期拥塞控制，已少用
5 重定向 通知主机改走更好的下一跳
11 超时 TTL 减为 0 或重组超时

5.11.3 ping 与 traceroute#

结论：ping 用类型 8/0 的回声请求—应答测往返时延；traceroute 用"TTL 逐次加 1 + ICMP 超时"逐跳发现路径。

机制与例：traceroute 先发 TTL=1，第一跳减 1 后为 0，回类型 11/0 的超时报文；再发 TTL=2……直到目的主机回类型 3、代码 3 的端口不可达。每个 TTL 发 3 个分组。

典型例题#

例 5-1 六节点拓扑跑 Dijkstra#

题目：无向拓扑如下（括号为代价），求 u 到各节点的最短路径与转发表。

u: v(2)  w(5)  x(1)
v: u(2)  w(3)  x(2)
w: u(5)  v(3)  x(3)  y(1)  z(5)
x: u(1)  v(2)  w(3)  y(1)
y: w(1)  x(1)  z(2)
z: w(5)  y(2)

步骤：

  1. 初始化 N'=u：D(v)=2、D(w)=5、D(x)=1，前驱均为 u；D(y)=D(z)=∞。
  2. 选 x（1）：D(w)=1+3=4<5（改经 x），D(y)=1+1=2。
  3. 选 y（2，与 v 并列）：D(w)=2+1=3<4，D(z)=2+2=4。
  4. 选 v（2）、w（3）：都不能改进 D(z)=4。
  5. 选 z（4），结束。
步骤 N' D(v),p(v) D(w),p(w) D(x),p(x) D(y),p(y) D(z),p(z)
0 u 2,u 5,u 1,u ∞ ∞
1 u,x 2,u 4,x — 2,x ∞
2 u,x,y 2,u 3,y — — 4,y
3 加 v — 3,y — — 4,y
4 加 w — — — — 4,y
5 全部 — — — — —

答案：D(v)=2、D(w)=3、D(x)=1、D(y)=2、D(z)=4；u→ z 走 u-x-y-z（1+1+2=4）。转发表中去往 x,y,w,z 的下一跳都是 x，只有去 v 的是 v。

例 5-2 一轮 Bellman-Ford 更新#

题目：x 与 y,z 相连，c(x,y)=2、c(x,z)=7、c(y,z)=1，初始只知直连邻居。求 x 收到邻居矢量后的距离矢量；随后 c(x,y) 由 2 变 5，再求一次。

步骤：

  1. 初始 Dₓ=[0,2,7]、D_y=[2,0,1]、D_z=[7,1,0]（顺序 x,y,z）。
  2. Dₓ(y)=\min2+0,7+1=2（经 y）；Dₓ(z)=\min2+1,7+0=3（经 y）。
  3. 得 Dₓ=[0,2,3]，有变化，向 y,z 发新矢量。
  4. 链路变贵：Dₓ(y)=\min5+0,7+1=5；Dₓ(z)=\min5+1,7+0=6，得 [0,5,6]。
  5. y 也测得变贵并通告；x 复查 Dₓ(z)=6 不变，收敛。

答案：Dₓ=[0,2,3]，链路变贵后 [0,5,6]，两轮收敛。"经 y 到 z"（3）比直连（7）便宜，这正是 Bellman-Ford 的价值。

例 5-3 距离向量无穷计数推演#

题目：A—B—C 链式拓扑，c(A,B)=1、c(B,C)=1，目的为 A。收敛后 A—B 断开，推演 B、C 的距离变化，并说明水平分割与毒性逆转如何终止。

步骤：

  1. 断开前：D_B(A)=1（直连），D_C(A)=2（经 B）。
  2. A—B 断开，B 直连失效；C 仍持旧值 2 并通告给 B。
  3. B 算得 D_B(A)=\min∞,1+2=3（经 C）。
  4. C 据 3 算出 4，B 再据 4 算出 5……每交换一次加 1。
轮次 D_B(A) D_C(A)
断开前 1（直连） 2（经 B）
1 3（经 C） 2
2 3 4（经 B）
3 5（经 C） 4
4 5 6（经 B）
收敛 16 16

答案：坏消息每轮只涨一点，要走到 16 才停。水平分割下 C 的下一跳是 B，C 不向 B 通告该路由，B 立即置 16；毒性逆转则明确通告 ∞。但三节点以上环路二者均无效，只能靠"定义无穷为 16"兜底。

例 5-4 BGP 选路：AS-PATH 长度与热土豆#

题目：AS1 的 1c 访问 203.0.113.0/24（在 AS3）。1a 经 AS2 学到，AS-PATH 为 "AS2 AS3"；1b 经 AS4 学到，AS-PATH 为 "AS4 AS3"。域内代价 1c-1a=11、1c-1b=3。求 1c 的选择；若 AS4 侧变为 "AS4 AS5 AS3" 如何；若本地偏好把 1a 设为 200、1b 设为 100 又如何。

步骤：

  1. 两条 AS-PATH 长度都为 2，未配本地偏好，第二级打平。
  2. 比到 NEXT-HOP 的域内代价：经 1b 为 3，经 1a 为 11。
  3. 选 1b——热土豆，尽快把分组甩出本 AS。
  4. AS4 侧变长（长度 3）后，第二级即选 1a，不再比域内代价。
  5. 本地偏好 200/100 时，第一级直接选 1a。

答案：默认选 1b；路径变长后选 1a；配策略后选 1a。BGP 的顺序是"策略 → 路径长度 → 域内代价"，不是端到端性能。

易错点与辨析#

  1. LS 是算法类别，OSPF 是协议：LS 指"先有拓扑再算最短路"，OSPF 是它的工程实现。
  2. DV 是算法，RIP 是协议：Bellman-Ford 是数学方法，RIP 把跳数、30 秒、UDP 520 固化下来。
  3. Dijkstra 得到的是最短路径树，不是路由表：转发表只留下一跳，多个目的可共用。
  4. 无穷计数不是"算法写错了"：是邻居互传了依赖对方的过时信息。
  5. 毒性逆转不是万能的：只能破两节点互指环路，三节点以上仍会计数到无穷。
  6. RIP 的 16 不是第 16 跳：它是"不可达"的约定值，故最大可用跳数是 15。
  7. OSPF 不走 TCP/UDP：直接封装在 IP 中（89），可靠性自己做。
  8. BGP 是应用层协议：跑在 TCP 179 上，但完成的是控制平面工作。
  9. iBGP 不跨 AS，也不改 AS-PATH：它只在 AS 内分发外部路由。
  10. 热土豆可能选中"更差"的出口：它只优化本 AS 内部那一段。
  11. SDN 集中的是控制平面：分组仍由交换机本地转发。
  12. ICMP 不是传输层协议：封装在 IP 中（协议号 1），不提供端口复用。
  13. traceroute 靠 TTL 与 ICMP 超时，不是"记录路由选项"。

6.1 链路层概述与服务#

节点、链路与帧#

结论：节点是运行链路层协议的任何设备（主机、路由器、交换机、Wi‑Fi 接入点）；链路是连接相邻节点的通信信道（有线、无线、LAN）；链路层的分组称为帧（frame）。链路层把数据报从一个节点送到物理上直接相连的下一个节点。

机制：一条端到端路径被切成若干段链路，每段可以跑不同的链路层协议（以太网、帧中继、802.11），因此同一个数据报在各段链路上的帧格式、地址、MTU 都可能不同。三层分工是：网络层管路由与转发（数据报），链路层管相邻节点间搬运（帧），物理层管无结构的原始比特流。

例子：主机 A → 路由器 R1 → 路由器 R2 → 主机 B 共三段链路。IP 数据报的源/目的 IP 全程不变，而帧的源/目的 MAC 每段都要重写，三段可用三种不同的链路层技术。

链路层提供的服务#

结论：成帧、链路接入、差错检测是基本服务；差错纠正、可靠交付、流控是可选服务；半双工/全双工描述链路的双工方式。

服务 做什么 备注
成帧 加头加尾，把数据报封装成帧，并在接收端从比特流中定界 基本服务，必有
链路接入 共享介质时协调各节点的发送次序（MAC 协议） 广播链路必需
差错检测 用 EDC 冗余比特判断帧是否出错 基本服务，检出后丢帧或重传

例子：以太网只提供成帧、链路接入、差错检测（出错丢帧，不确认不重传）；802.11 增加了链路级 ACK 与重传；PPP 既无纠错也无重传。

链路层在哪里实现#

结论：链路层主体在网络适配器（网卡 / NIC）上实现，核心是链路层控制器专用芯片；实现方式可以是硬件、固件或软件，是协议栈中软硬件交接的地方。

机制：网卡通过总线（PCIe）与主机相连，芯片完成组帧、链路接入、检错、可靠交付、流控等；主机上的驱动软件负责与网络层接口、组装寻址信息、激活硬件、响应控制器中断、处理差错并把数据报上交网络层。路由器中链路层在线卡上实现，物理层功能也由线卡/适配器完成。

例子：收帧流程——网卡收到信号 → 定界成帧 → 校验 FCS → 比对目的 MAC → 通过 DMA 写入主机内存 → 发中断 → 驱动把数据报交给 IP 层。

6.2 差错检测与纠正#

差错的类型与编码分类#

结论：单比特错由随机信道热噪声引起，一次只影响 1 位；突发错由瞬间脉冲噪声引起，一次影响连续许多位，用突发长度描述其影响的最大位数。检错码只能判断“出错了”，纠错码还能定位并纠正。

机制：发送端对受保护的数据 D（含帧头字段）计算校验位 EDC，附在帧中；接收端用同一算法复算并比对。检错永远不是 100% 有效，只是漏检概率极低；EDC 越长保护越强，开销也越大。检错码通常与反馈重传（ARQ）配合完成差错恢复。

例子：以太网 FCS 用 32 位 CRC，对随机错误的漏检概率约 2⁻³²。

码字、海明距离与检错/纠错能力#

结论：码字 = m 位数据 + r 位冗余，有效编码集含 2ᵐ 个码字；两码字的海明距离是对应位取值不同的位数；编码集的海明距离 d_\min 是任意两个有效码字距离的最小值。若要求检出 d 位错，需 d_\min≥ d+1；若要求纠正 t 位错，需 d_\min≥ 2t+1；若同时要求检出 d 位、纠正 t 位（d>t），需 d_\min≥ d+t+1。

机制：把每个有效码字看成球心、半径 t 的“纠错球”，d_\min≥ 2t+1 保证球互不相交；收到无效码字时，纠正到距离最近的那个球心。检错只需要“无效码字不落在任何有效码字上”，所以门槛比纠错低一半。

例子：d_\min=2 只能检 1 位错；d_\min=3 可检 2 位、纠 1 位；d_\min=4 可检 3 位，或“检 2 位 + 纠 1 位”。

单比特奇偶校验#

结论：增加 1 位校验位，使整个码字（含校验位）中 1 的个数为偶数（偶校验）；编码集 d_\min=2，只能检出奇数个比特错，突发差错下检错率约 50%。

机制：偶数个比特翻转不改变 1 的个数的奇偶性，所以必然漏检；校验位本身也计入统计。

例子：数据 1011001 有 4 个 1，偶校验位取 0，发送 10110010；若收到 10110011 则 1 的个数为 5（奇数），判出错。

二维奇偶校验#

结论：把数据排成 i 行 j 列矩阵，每行、每列各加 1 位校验位，d_\min=3，可纠正 1 位错（含校验位自身出错）、检出但不纠正 2 位错，且善于检测突发错。

机制：某位翻转会使所在行、所在列的校验同时失败，行列交叉处即错误位置，翻转即可纠正，无需重传（前向纠错 FEC 的基础）。突发错误若只打坏一行中的连续若干位，每列至多错 1 位，仍可逐列纠正。

例子：4×4 数据块加行列校验后，若第 2 行第 3 列翻转，第 2 行与第 3 列的校验位同时报错，定位后直接改正。

因特网校验和#

结论：把数据（含首部）看成 16 位整数序列，做反码求和（进位回卷加到低位），再按位取反得到校验和；接收端把校验和字段一起求和，结果全 1（0xFFFF）视为未检出错误。

机制：反码加法的进位要回卷，取反使“数据 + 校验和 = 全 1”。优点是分组开销小、软件实现快；缺点是保护能力弱于 CRC。

例子：0x8FFF 与 0x9000 相加为 0x11FFF，回卷得 0x2000，取反得校验和 0xDFFF；接收端 0x8FFF+0x9000+0xDFFF 回卷后为 0xFFFF。

CRC：把比特串看成多项式#

结论：CRC（循环冗余校验）是多项式编码，把比特串看作一元多项式的系数（1011 即 x³+x+1）。生成多项式 G(x) 为 r+1 位、最高位与最低位均为 1；消息多项式 M(x) 有 m 位；冗余多项式 R(x) 有 r 位。编码：R(x)=xʳM(x) mod G(x)，码多项式 T(x)=xʳM(x)+R(x)，即在数据后补 r 个 0 做模 2 除法，余数就是 r 位冗余，接在数据后发出。检验：T(x) mod G(x)=0 判为正确。

机制：模 2 运算中加法与减法都是异或，不产生借位；除法按“对齐最高位、遇 1 就异或”逐步右移完成。检错能力：所有单比特错、所有长度 ≤ r 的突发错必被检出；长度 >r 的突发错漏检概率约 2⁻ʳ；若 G(x) 含因子 (x+1)，还能检出所有奇数个比特错。

例子：G=1001（即 x³+1，r=3），数据 101110 → 补 3 个 0 得 101110000，除得余数 011，发送 101110011（完整竖式见例题 1）。

为什么链路层用 CRC、传输层用校验和：传输层在主机中由操作系统用软件实现，需要简单快速；链路层在适配器里由专用硬件实现，能承担更复杂的 CRC 运算。

6.3 多路访问协议#

两类链路与“冲突”#

结论：点到点链路只连接一个发送方和一个接收方（全双工链路可看成两条单工链路）；广播链路连接多个节点共享同一介质，任一点发送可被其他节点收到。冲突指两个以上节点同时发送，信号叠加导致接收失败。

机制：多址接入协议（MAC 协议）是分布式算法，决定“哪个节点何时可以发送”。难点在于协商本身也必须占用信道，没有带外信道可供协同。理想 MAC 的四条标准：①只有一个节点发送时可达速率 R；②M 个节点同时活跃时每个平均 R/M；③完全分布式，无需中心协调节点、无需时钟/时隙同步；④简单、开销小。

例子：以太网总线、Wi‑Fi 信道、卫星上行信道都是广播链路；家庭宽带拨号用的 PPP 链路是点到点链路，不需要 MAC 协议。

协议分类：划分、竞争、轮流#

类别 是否冲突 轻负载 重负载 典型协议
信道划分 不会 利用率低（分到的份额用不完） 公平稳定 FDM、TDM、CDMA
随机接入 会冲突，冲突后恢复 利用率高（时延小） 冲突严重 ALOHA、时隙 ALOHA、CSMA/CD
轮流访问 不会 有轮询/令牌开销 利用率居中 轮询、令牌传递

信道划分：FDM、TDM、CDMA#

结论：FDM 把频谱划成若干频段，每节点固定一个（带宽 R/N）；TDM 把时间划成帧，每帧分 N 个时隙，每节点固定一个时隙，轮空则浪费；两者都能消除冲突且公平，但每节点被限制在 R/N，且必须等待轮次。CDMA 让所有用户同时同频发送，靠正交码片序列区分。

机制：CDMA 中每个比特用 m 位码片表示：发 1 送码片序列 s，发 0 送 −s；不同用户的码片正交（内积为 0）。接收端用 s 与收到的混合信号做内积并除以 m 即可还原该用户的数据，其他用户的信号因正交而抵消。

例子：s=(1,1,1,−1,1,−1,−1,−1)，m=8。发比特 1 送 s；接收 s 与 s 内积为 8，除以 8 得 1，判为 1；若收到 −s 则内积 −8，判为 0。

随机接入：ALOHA 与时隙 ALOHA#

结论：随机接入不划分信道，节点有数据就以 R 发送，冲突后各自独立地随机等待再重发。纯 ALOHA 随时可发，易损期为两个帧时，最大效率 1/2e≈18.4%；时隙 ALOHA 只能在时隙起点发送，易损期缩短为一个帧时，最大效率 1/e≈36.8%。

机制：时隙 ALOHA 假设帧等长、时隙等长、节点时钟同步、可在时隙结束前检测冲突。成功时隙 = 恰好一个节点发送的时隙；冲突后在后续每个时隙以概率 p 重传，直到成功。优点是单活跃节点可满速率、分布式、简单；缺点是冲突时隙与空闲时隙都浪费，且时隙版需要同步。

例子：100 个节点各有帧要发，每时隙以 p=0.01 发送，则某时隙恰好一人发送的概率为 100×0.01×0.99⁹⁹≈0.37，即效率接近 37%，正好是 1/e 的量级。

CSMA 家族与 CSMA/CA#

结论：CSMA 是“发送前先监听”。1‑坚持：信道忙则持续监听，一空闲立即发送，冲突概率高；非坚持：忙则随机等一段再听，冲突少但时延大；p‑坚持：空闲时以概率 p 发送。CSMA/CD 进一步“边发边听”，用于有线以太网；CSMA/CA 用“先预约、后确认”的机制，用于无线。

机制：无线网卡无法在发送的同时可靠检测冲突（自身发射信号远强于接收信号），因此 802.11 改为发送前用 RTS/CTS 预约信道、收到数据后回 ACK，并对每个单播帧做链路级重传。

例子：总线以太网用 CSMA/CD；Wi‑Fi 用 CSMA/CA；同轴电缆早期以太网也是 CSMA/CD，但现代交换式以太网是全双工点对点，不再需要它。

轮流访问：轮询与令牌#

结论：轮询由主节点依次“点名”，被点到的从节点才能发送；令牌传递让一个特殊令牌帧沿环流动，持有令牌者才可发送。两者都无冲突、效率居中，代价是额外控制开销与单点故障风险（主节点故障、令牌丢失或重复）。

机制：轮询的时延随节点数线性增长；令牌环需令牌维护（丢失重发、重复清除），可靠性设计复杂。

例子：蓝牙微微网由主设备轮询从设备；令牌环网（802.5）、FDDI 用令牌传递。

6.4 CSMA/CD：冲突检测、退避与效率#

冲突检测与争用期#

结论：CSMA/CD 发送时同时监听，把发送信号与接收信号比较，不一致即判定冲突，立即停止发送并发出强化干扰信号（jam），然后进入退避。最坏情况下需 2τ（τ 为单程最大传播时延）才能确认“没有冲突”，这段时间称为争用期（碰撞窗口）。

机制：A 的信号要经 τ 才到最远端 B；若 B 恰在 A 到达前开始发送，冲突在 B 处发生，A 还要再等 τ 才能感知，故最坏 2τ。10 Mbps 以太网取争用期 51.2 μs，即 512 比特时间。

例子：10 Mbps、τ=25.6 μs 的以太网，发送方在发出 512 bit 后仍未检测到冲突，就可以确认已独占信道。

最小帧长 64 B#

结论：为保证“发送方在发完之前一定能检测到冲突”，帧的发送时延必须不小于争用期：L_\min=2τ· R。以太网取 L_\min=512 bit = 64 B。

机制：若帧太短，冲突信号在帧发完之后才返回，发送方无从判断，CSMA/CD 失效，只能靠上层超时重传，效率骤降。速率提高时 L_\min/R 变小，允许的最大距离随之缩短，这是快速以太网限制网段长度的根本原因（千兆以太网另用载波延伸把最小帧等效放大到 512 B）。

例子：R=10 Mbps、2τ=51.2 μs，则 L_\min=51.2×10⁻⁶×10⁷=512 bit；若升到 100 Mbps 仍用 64 B，则允许的单程时延只有 2.56 μs，网段长度约为 512 m。

二进制指数退避#

结论：第 i 次冲突后，从 0,1,…,2ⁱ-1 中随机取整数 K，等待 K 个 512 比特时间后重发；i 超过 10 后按 10 计算（窗口封顶 1023）；连续冲突 16 次则放弃并向高层报错。

机制：冲突次数越多，可选等待窗口越大，从而在重负载下降低再次碰撞的概率；随机化保证同时冲突的站点不会永远同步重试。窗口封顶避免退避时间无界增长。

例子：第 1 次冲突 K∈{0,1}；第 2 次 K∈{0,…,3}；第 3 次 K∈{0,…,7}；第 10 次及以后 K∈{0,…,1023}。

效率公式#

结论：CSMA/CD 的信道效率近似为 η=1/(1+5a)，其中 a=τ/T₀ 为单程传播时延与帧发送时延之比。a 越小效率越高。

机制：每个“竞争周期”里，真正传数据的时间是 T₀，而冲突窗口 2τ 及其后的退避、帧间隙构成固定浪费；把浪费折算成 5τ 得到该近似式。速率升高使 T₀ 变小、a 变大，效率反而下降——这就是“带宽更高不等于效率更高”。

例子：R=10 Mbps、L=1000 bit、d=2 km、v=2×10⁸ m/s，则 η≈66.7%（见例题 4）。

6.5 链路层寻址与 ARP#

MAC 地址#

结论：MAC 地址（物理地址、硬件地址、LAN 地址）长 6 B = 48 bit，由 IEEE 分配前 3 字节（OUI），厂商保证后 3 字节唯一；固化在网卡 ROM 中，具有扁平结构，与所处位置无关。类型：单播（首字节最低位为 0）、多播（为 1）、广播（全 1，FF‑FF‑FF‑FF‑FF‑FF）。

机制：网卡只把“目的地址等于自己的单播帧、所有广播帧、自己已加入的多播帧”交给主机；若设为混杂模式则全部上交。拥有多个接口的主机或路由器有多个 MAC 地址；链路层交换机自身的接口没有 MAC 地址，它对主机透明。适配器的过滤让主机不必为无关帧产生中断。

例子：00‑1A‑2B‑3C‑4D‑5E 中，00‑1A‑2B 是厂商号，3C‑4D‑5E 是厂商内部编号。

有了 MAC 地址，为什么还要 IP 地址#

结论：MAC 扁平、不含位置信息，无法在因特网范围定位接口；IP 层次化（网络号 + 主机号），可聚合路由、快速查表。两者解耦还让链路层能为任意网络层协议服务。

机制：若网卡用网络层地址，换网段或加电时都要重配；若网卡不看地址、把每帧都上交，主机会被同一广播域内所有帧打断。故各层需各自的寻址方案，保持层次独立。

例子：笔记本从宿舍搬到教室，MAC 不变，IP 由 DHCP 重新分配。

ARP：由 IP 地址求 MAC 地址#

结论：每台主机/路由器维护 ARP 表，表项为 <IP 地址, MAC 地址, TTL>（典型 20 min）。查不到时广播 ARP 请求，目标主机单播回应，表中随即缓存。ARP 是即插即用的。

机制：①A 构造 ARP 请求，填入自己的 MAC/IP 与目标 IP；②封装在目的 MAC 为 FF‑FF‑FF‑FF‑FF‑FF 的广播帧中发出；③各节点比对目标 IP 与本机 IP，只有匹配者（B）响应；④B 构造 ARP 响应，交换发送方与目标字段并填入自己的 MAC；⑤以 A 的 MAC 为目的地址单播回送；⑥A 更新 ARP 表后发送数据报。节点还可从收到的 ARP 请求中被动学习地址绑定；主机启动时广播自己的映射可检测 IP 冲突。

例子：A(192.168.1.10) 要发数据给同子网的 B(192.168.1.20)，广播 ARP 请求后只有 B 回应，A 缓存 <192.168.1.20, BB> 约 20 min。

跨子网转发：MAC 逐跳改变#

结论：数据报跨子网时，源/目的 IP 地址端到端不变，源/目的 MAC 地址逐段改变。源主机解析的是默认网关的 MAC，而不是最终目的主机的 MAC。

机制：A 发现目的 IP 不在本子网，于是把数据报交给默认网关 R；帧的目的 MAC 填 R 的入接口 MAC，IP 目的仍是 B。R 收到后拆帧、上交 IP 层、查转发表得到下一跳与出接口，若 B 与出接口直连则 ARP 求 B 的 MAC，重新封装成新帧（源 MAC 改为 R 的出接口 MAC），TTL 减 1 并重算首部校验和。

例子：完整六步封装/解封装过程见例题 5。

6.6 以太网#

帧格式#

结论：以太网帧由前导码、目的地址、源地址、类型、数据、FCS 组成；帧长（不含前导码）为 64~1518 B。

以太网帧（DIX Ethernet V2）
┌──────────┬──────────┬──────────┬────────┬──────────────┬────────┐
│ 前导码 8B │ 目的MAC 6B│ 源MAC 6B │ 类型2B │ 数据 46~1500B │ FCS 4B │
└──────────┴──────────┴──────────┴────────┴──────────────┴────────┘
前导码 = 7B 的 10101010 + 1B 的 10101011(SFD)，仅用于收发同步，不计入帧长
类型   = 0x0800(IPv4) / 0x0806(ARP) / 0x8100(802.1Q VLAN)
FCS    = CRC-32，覆盖目的MAC到数据全部字段

机制：数据字段最少 46 B，不足则填充，从而保证整帧不小于 64 B（CSMA/CD 的最小帧长要求）；最多 1500 B 即 MTU，超出由 IP 层分片。帧与帧之间要求 96 比特时间的帧间隙，让网卡有时间处理下一帧。

例子：一个 20 B 的 IP 数据报要填充到 46 B 才能封装，接收方再按 IP 首部的总长度字段去掉填充。

无连接、不可靠#

结论：以太网向网络层提供无连接（收发双方网卡之间没有握手）和不可靠（无 ACK/NAK，CRC 错的帧直接丢弃）的服务，丢失的帧由 TCP 或应用层恢复。

机制：有线链路误码率极低，加确认会显著增加适配器复杂度与时延；把可靠性交给端到端机制更划算。若上层没有可靠传输（如 UDP），则数据确实会丢。

例子：ping 用 ICMP，链路丢帧就表现为丢包；TCP 连接上的丢帧则由超时重传补回。

从集线器到交换机#

设备 层次 冲突域 双工 是否需要 CSMA/CD
集线器 物理层（多口中继器） 所有端口同一个 半双工 需要
交换机 链路层 每个端口独立 全双工 不需要

机制：集线器只把信号放大广播到所有端口，两个端口同时收帧就冲突；交换机在端口间存储转发帧，每条主机—交换机链路是独立碰撞域，可并行通信。注意：交换机隔离冲突域，但不隔离广播域。

例子：集线器同时从两个接口收到帧就发生一次冲突并需重传；换成交换机后两台主机可同时满速率通信。

6.7 交换局域网#

交换机：自学习、泛洪、过滤、转发#

结论：交换机依据“源 MAC 学习、目的 MAC 转发”透明工作：收到帧就把 <源 MAC, 入端口, 时间戳> 记入交换表；再查目的 MAC——命中且出端口等于入端口则过滤丢弃，命中且不同则从该端口转发，未命中则向除入端口外的所有端口泛洪（广播帧同样泛洪）。

机制：交换表项带时间戳，长期不刷新则老化删除，以适应主机移动与网卡更换。交换机是即插即用的，无需配置，也不改写帧的任何字段。

例子：四台主机接在交换机 1~4 端口，帧序列推演见例题 3。

生成树协议#

结论：为提高可靠性而增加冗余链路会形成环路，导致广播帧无限循环（广播风暴）与转发表不稳定。生成树协议（STP，802.1D）在物理有环的拓扑上逻辑地选出一棵无环生成树，被阻塞的端口不收发数据帧，只保留为备份。

机制：①选根桥（桥 ID 最小者）；②每台非根交换机选到根路径代价最小的端口为根端口；③每条 LAN 选出一个指定桥，其连接该 LAN 的端口为指定端口；④既非根端口又非指定端口的端口置为阻塞；⑤各桥周期性交换 BPDU，拓扑变化后重新收敛。

例子：三台交换机两两相连构成三角形，STP 阻塞其中一条链路；该链路断开时被阻塞端口自动启用，网络恢复连通。

交换机 vs 路由器#

维度 链路层交换机 路由器
工作层次 链路层 网络层
转发依据 目的 MAC 地址 目的 IP 地址（最长前缀匹配）
隔离冲突域 是（每端口一个） 是
隔离广播域 否（除非划分 VLAN） 是（默认不转发广播）
转发表来源 自学习（数据平面） 路由协议 + 配置（控制平面）
即插即用 是 否，需配置地址与路由
典型规模 小网络、即插即用场景 大规模、异构网络互联

机制：交换机转发快、成本低、无需配置，但网络规模大时广播域过大；路由器能隔离广播、支持层次编址与策略，但每包处理开销大。

例子：一个机房内部用交换机连接主机，机房出口用路由器连到校园网，从而把广播限制在机房内。

VLAN#

结论：VLAN 在一台交换机上逻辑划分多个广播域，无需额外布线。802.1Q 标签长 4 B：TPID 0x8100（2 B）+ 优先级 3 bit + DEI 1 bit + VLAN ID 12 bit，可用 VLAN 号 1~4094。

机制：access 端口只属于一个 VLAN，进出不带标签；trunk 端口承载多个 VLAN 的帧，用标签区分。同一 VLAN 内二层转发，不同 VLAN 之间必须经路由器或三层交换机（单臂路由或三层接口）转发。因为广播只在 VLAN 内泛洪，VLAN 天然隔离广播域。

例子：一台 24 口交换机划分为 VLAN 10（教学）与 VLAN 20（办公），两组的广播互不可见；若要互访，须经三层设备路由。

MPLS 简述#

结论：MPLS 在链路层与网络层之间用固定长度标签转发，常被称为“2.5 层”。入口路由器压入标签（push），核心路由器按标签交换（swap），出口弹出标签（pop），全程不必查目的 IP。

机制：由标签分发协议（LDP/RSVP‑TE）预先建立标签交换路径 LSP，转发表只按“入标签 → 出标签 + 出接口”匹配，速度比最长前缀匹配快；标签栈支持嵌套，因而能做流量工程、VPN 与快速重路由。

例子：运营商骨干网中，入口路由器为进入某 VPN 的分组压入外层标签，核心只按标签转发，出口弹出标签后再按 IP 送达用户网络。

典型例题#

例题 1：CRC 计算与验证（G=1001，数据 101110）#

求解：G=1001 为 4 位，故 r=3，余数与冗余位都是 3 位。

步骤①  数据后补 3 个 0：101110000
步骤②  模 2 除法（遇最高位为 1 就与 1001 异或，逐步右移）

  101110000  ⊕1001(前4位)  → 001010000
  001010000  ⊕1001(第3~6位) → 000011000
  000011000  ⊕1001(第5~8位) → 000001010
  000001010  ⊕1001(第6~9位) → 000000011
步骤③  余数 R = 011，故发送码字 T = 101110 || 011 = 101110011

验证：

  101110011  ⊕1001(前4位)  → 001010011
  001010011  ⊕1001(第3~6位) → 000011011
  000011011  ⊕1001(第5~8位) → 000010001
  000010001  ⊕1001(第6~9位) → 000000000
余数为 000 → 传输正确

推广：若接收端收到 1001001，除 1001 得余数 001（最高位 1 已被消去，剩 001），余数非 0，判定出错。注意：CRC 只保证“检出”，不指出错在哪一位，纠错仍需重传。

例题 2：海明距离与检错/纠错能力#

题目：编码集 C=00000, 01101, 10110, 11011，求 d_\min，并给出可检错位数与可纠错位数。

步骤：

  1. 逐对求异或后 1 的个数：00000 与 01101、10110、11011 的距离分别为 3、3、4。
  2. 01101 与 10110 异或为 11011，距离 4；01101 与 11011 异或为 10110，距离 3。
  3. 10110 与 11011 异或为 01101，距离 3。
  4. 取最小值：d_\min=3。

结论：可检出 d_\min-1=2 位错，可纠正 ⌊(d_\min-1)/2⌋=1 位错；若要“检 2 位 + 纠 1 位”同时成立，需 3≥ 2+1+1=4，不满足，故本码集不能同时做到。

例题 3：交换机转发表自学习推演#

题目：交换机 4 个端口，主机 A、B、C、D 分别接在端口 1、2、3、4，初始交换表为空。依次到达 6 个帧，写出每步动作与最终交换表。

序号 源 MAC 目的 MAC 入端口 学习结果 查表与动作
1 A C 1 记 A→1 C 未知，向 2、3、4 泛洪
2 C A 3 记 C→3 A→1 且 ≠3，只从端口 1 转发
3 B A 2 记 B→2 A→1，从端口 1 转发
4 D C 4 记 D→4 C→3，从端口 3 转发
5 A D 1 A→1 已存在，刷新时间戳 D→4，从端口 4 转发
6 D B 4 D→4 已存在，刷新 B→2，从端口 2 转发

最终交换表：A→1、B→2、C→3、D→4。

要点：①学习只看源 MAC，转发只看目的 MAC；②若某帧从端口 3 进入、而目的 MAC 对应的出端口也是 3（同端口下挂了集线器），则该帧被过滤丢弃，不再转发；③目的未知与广播帧都泛洪，但泛洪不包含入端口。

例题 4：CSMA/CD 效率与最小帧长#

题目：10 Mbps 以太网，帧长 1000 bit，两站相距 2 km，信号传播速率 2×10⁸ m/s。求效率；再求该速率下 64 B 最小帧所允许的最大距离。

步骤：

  1. 单程传播时延 τ=2000/(2×10⁸)=10 μ s。
  2. 帧发送时延 T₀=1000/(10×10⁶)=100 μ s。
  3. a=τ/T₀=0.1。
  4. 效率 η=1/(1+5a)=1/1.5≈66.7%。
  5. 由 L_\min=2τ R：2τ=512/(10×10⁶)=51.2 μ s，故 τ_\max=25.6 μ s，d_\max=25.6×10⁻⁶×2×10⁸=5120 m（标准实际取 2500 m 并为中继器延时留余量）。
  6. 若速率升到 100 Mbps 而最小帧仍是 64 B，则 2τ=5.12 μ s，τ_\max=2.56 μ s，d_\max≈512 m：网段必须缩短，否则 CSMA/CD 失效。

例题 5：主机 A 到另一子网主机 B 的封装与 MAC 变化#

题目：子网 1 为 192.168.1.0/24，A=192.168.1.10（MAC 记为 AA），网关接口 R1=192.168.1.1（MAC 记为 R1）；子网 2 为 192.168.2.0/24，B=192.168.2.20（MAC 记为 BB），R 的另一接口 R2=192.168.2.1（MAC 记为 R2）。写出全过程。

步骤：

  1. A 用子网掩码判断 192.168.2.20 不在本子网，决定交给默认网关 192.168.1.1。
  2. A 查 ARP 表无 192.168.1.1，广播 ARP 请求（目的 MAC=FF‑FF‑FF‑FF‑FF‑FF），R 以 R1 单播应答，A 缓存该映射。
  3. A 封装：IP 首部 src=192.168.1.10、dst=192.168.2.20、TTL=64；以太帧 src=AA、dst=R1、类型=0x0800，网卡计算 FCS 后发出。
  4. R 收到：校验 FCS、目的 MAC 等于 R1，拆帧上交 IP 层；查转发表得下一跳 192.168.2.20、出接口为接口 2；TTL 减为 63 并重算首部校验和。
  5. R 查 ARP 表无 192.168.2.20，在接口 2 广播 ARP 请求，B 以 BB 单播应答。
  6. R 封装新帧：src=R2、dst=BB，重新计算 FCS 后发出；B 校验通过、目的 MAC 匹配、IP 目的匹配，交给上层 TCP。
链路段 源 MAC 目的 MAC 源 IP 目的 IP
A → R AA R1 192.168.1.10 192.168.2.20
R → B R2 BB 192.168.1.10 192.168.2.20

要点：IP 地址全程不变，MAC 地址逐段重写；A 解析的是网关 MAC 而非 BB；若 A 的 ARP 表里缓存了 BB 也没用——目的 MAC 填 BB 的帧在子网 1 里无人接收。

7.1 要素与分类#

三要素与自组织网络#

定义：无线网络 = 无线主机 + 基站 + 无线链路，无基站时称自组织（ad hoc）网络。机制：主机可静止可移动，无线 ≠ 移动；基站有线接入固定网络并协调关联主机的传输；链路须用多址协议避碰撞。自组织网络的节点自备路由、地址分配与名字转换，只与邻居直连并互转发，既是终端又是路由器。例：教室 60 台笔记本共享一个 AP；灾区设备互转发组成 MANET。

分类：跳数 × 有无基础设施#

类别 基础设施 跳数 例子
单跳 + 有 有 1 Wi-Fi、4G/5G
多跳 + 有 有 多 无线网状网
单跳 + 无 无 1 蓝牙
多跳 + 无 无 多 MANET、VANET

例：802.11 ad hoc 两台直连属单跳无基础设施，多台互转发即多跳无。切换是终端改换基站的过程。

7.2 无线链路的特征#

三个物理难题#

定义：路径损耗、干扰、多径传播，共同导致距离受限、误码率高。机制：能量随距离扩散与穿透而衰减；同频源与噪声叠加压低信噪比；反射使信号沿多条路径到达、相位不同而抵消。故链路层用强 CRC + ARQ 重传，不像以太网那样丢弃错帧。例：走廊尽头连宿舍 AP 打不开网页，是 SNR 低使大量帧 CRC 失败，而非没信号。

SNR 与 BER 的权衡#

定义：SNR_dB=10\log₁₀(S/N)，SNR 越高越易提取信号，BER 越低。机制：①同物理层提功率 → SNR↑ → BER↓，但功率有上限且加剧干扰；②给定 SNR，64-QAM 等高速调制在低 SNR 下 BER 急剧恶化，BPSK 更皮实，应在满足 BER 前提下选吞吐最高的物理层；③移动使 SNR 时变，需速率自适应，降速率换距离。例：802.11 连续两帧无 ACK 降一档速率，连续 10 个 ACK 再升档。

隐藏终端与暴露终端#

定义：隐藏终端——A、C 都能与 B 通信却彼此听不到，同发时在 B 处冲突而自己察觉不到；暴露终端——A、B 互听得到但目标 AP 互不干扰，B 却不必要退避。机制：侦听只回答"我周围有人发吗"，决定成败的却是"接收方周围有人发吗"；故 CSMA/CD 在多跳无线失效，暴露终端无根本解法。例：A—B—C 三房间，A、C 同发给中间的 B，信号在 B 处叠加成垃圾，双方等 ACK 超时才知失败。

CDMA#

定义：属信道划分类多址协议，用户同时同频发送，靠各自正交码区分。机制：每站分配长 M 的码片序列 c（分量 ±1），两两正交 cᵢ· cⱼ=0，自内积 cᵢ· cᵢ=M；编码 s=d· c（1 发码、0 发反码），空中为叠加 S=Σₖ dₖ cₖ；解码 d=1/MS· c，他站投影为 0 被滤除。1 比特占 M 码片，带宽扩展 M 倍。例：三个 8 位正交码同发，三次内积即还原三个比特（例题 1）。

7.3 802.11 体系结构#

BSS、AP、SSID、信道#

定义：基本服务集 BSS = 若干站点 + 一个 AP，AP 经交换机/路由器接入因特网；无 AP 者为 ad hoc 模式。机制：站点与 AP 无线接口各有全球唯一 6 B MAC；AP 连路由器的有线端口无 MAC（对路由器透明），故 802.11 需三个地址字段；2.4 GHz 划为 11 个部分重叠信道，每 BSS 一个，相邻 AP 宜用 1/6/11；SSID 即网络名。例：每层 6 个 AP，SSID 统一 CampusNet，信道按 1/6/11 循环。

beacon、扫描与关联#

定义：站点收发数据前必须关联一个 AP：发现 → 选择 →（认证）→ 关联 → DHCP 取址。机制：AP 每约 100 ms 广播 beacon（含 SSID、MAC）；被动扫描逐信道听 beacon 再关联，慢；主动扫描广播 probe request、收 probe response 后择优，快。例：手机开 Wi-Fi 立刻列出网络名，即主动扫描的 probe response 汇总。

被动: 主机 --听 beacon--> AP --关联请求--> AP --响应--> DHCP
主动: 主机 --probe req--> 各 AP --probe resp--> 关联请求/响应 --> DHCP

802.11a/b/g/n/ac/ax 都用 CSMA/CA、都支持两种模式、帧格式相同，差别在频段与物理层（2.4 GHz／5 GHz，11 Mbps 至 9.6 Gbps，n 起引入 MIMO）。

7.4 802.11 MAC：CSMA/CA#

为什么不能检测冲突#

定义：802.11 用 CSMA/CA，只侦听不检测；以太网用 CSMA/CD，边发边检测。机制：①发射功率远大于接收信号（约 100 dB 级），自身信号淹没接收端；②隐藏终端使冲突发生在 AP 处，发送方无处检测；③边发边听需全双工射频，代价过高；④帧一旦开始必须发完，检测到也已整帧损失。故只能"避免"。例：以太网冲突只损失冲突窗口，无线撞一次损失整帧并阻塞他人。

无预约的 CSMA/CA#

定义：SIFS < DIFS，SIFS 给必须优先的 ACK/CTS，DIFS 给想竞争的数据帧。机制：①侦听；②空闲则等 DIFS 后发；③忙则取随机退避值（按时隙），空闲递减、忙时冻结，归零才发；④发完整帧等 ACK；⑤超时则在更大 CW 内重选退避重传；收方正确收帧后等 SIFS 回 ACK。为何必须 ACK：误码高又无法靠检测发现失败，只能由收方确认；但 ACK 不能根除冲突。例：802.11b 的 SIFS 10 μs、时隙 20 μs、DIFS 50 μs。

RTS/CTS 预约#

定义：可选握手，用短帧预约信道，缓解隐藏终端。机制：①发送方发 RTS，写明"数据 + ACK"占用时长；②AP 用 CTS 广播相同时长；③听到 CTS 者（含隐藏终端）按 NAV 沉默；④数据后 AP 于 SIFS 回 ACK。RTS/CTS 也可能碰撞，但帧短损失小；开销大，短帧不用。例：C 听不到 A 的 RTS 却听到 AP 的 CTS，于是沉默到 ACK 结束，冲突消除。

DCF/PCF 与帧地址#

机制：DCF 为 CSMA/CA（+ 可选 RTS/CTS），终端竞争，必须支持；PCF 由 AP 轮询终端有无数据，无竞争，可选；二者交替工作，周期称 CFP。帧的帧控制字段给出类型与子类型（RTS、CTS、ACK、Data），持续期字段供 RTS/CTS 预留时间，序号用于可靠传输。

地址 含义
1 接收该帧的无线站点（AP 或主机）
2 发送该帧的无线站点
3 AP 所连路由器接口的 MAC
4 仅 ad hoc 转发时使用

例（四步）：①R1 用 ARP 得 H1 的 MAC，发 802.3 帧（目的 H1、源 R1）给 AP；②AP 转 802.11 帧：地址 1 = H1、2 = AP、3 = R1；③H1 回复：地址 1 = AP、2 = H1、3 = R1；④AP 转回 802.3 帧：源 H1、目的 R1。

7.5 蓝牙与蜂窝#

蓝牙 / 802.15#

定义：IEEE 802.15.1，2.4 GHz，10 m 级无线个域网。机制：1 主设备 + 最多 7 从设备组成 piconet，多个交叠成 scatternet；625 μs 时隙由主设备轮询决定谁发（无竞争），并每秒跳频 1600 次。例：手机（master）连耳机（slave），耳机不能抢时隙。

4G/5G 概述#

定义：蜂窝用"基站 + 频率复用"广域覆盖，属有基础设施的多跳网络。机制：4G LTE 接入网为 eNodeB，核心网 EPC（SGW/PGW/MME），下行 OFDMA、上行 SC-FDMA，全 IP；5G NR 扩展 Sub-6 GHz 与毫米波，引入大规模 MIMO、波束赋形、网络切片；蜂窝切换由网络侧主导。例：出地铁时通话不断，因切基站由网络控制。

7.6 移动性管理#

术语与注册#

术语 含义
归属网络 / 归属代理 永久居所（128.119.40/24）；在外地时代其执行移动管理的实体
永久地址 归属网络中的 IP，移动中不变（128.119.40.186）
外地网络 / 外地代理 当前所在网络（79.129.13/24）；为其服务的实体
转交地址 COA 在外地网络上的地址（79.129.13.2）

注册五步：①移动节点向外地代理发注册请求（UDP 434，含永久地址、COA、归属代理地址、寿命、认证）；②外地代理记录并转给归属代理；③归属代理认证后写绑定表并回响应；④外地代理记入转发表并回传响应；⑤回到归属网络时注销。离开外地网络无需显式注销，新 COA 自动覆盖。本质：IP 兼有身份与位置含义，移动管理即身份不变 + 位置隐藏（COA + 隧道）。

间接选路#

定义：通信者始终发往永久地址，归属代理截获后用隧道转给外地代理，回包由移动节点直发。机制：①目的写永久地址，数据报被路由到归属网络；②归属代理以 ARP 代理截获（用自己的 MAC 应答永久地址的 ARP）；③查绑定表做隧道封装，外层目的 = COA、内层仍是原数据报——不能直接把目的改成 COA；④外地代理解封装后按永久地址交付。三角路由：通信者 → 归属网络 → 移动节点，同网时尤低效；优点是对通信者透明，换网络会话不断。

直接选路与对比#

机制：①通信者向归属代理问得 COA；②隧道发往外地代理（外层 COA、内层永久地址）；③解封装交付；④回包直发。再次移动时把最初的外地代理标为锚点，新外地代理告知新 COA，锚点解封装后再封一层新头转给新 COA（两段隧道）。

维度 间接选路 直接选路
透明性 对通信者透明 不透明
效率 低（三角路由） 高
移动中保会话 简单（更新 COA） 复杂（锚点两段隧道）

移动 IP（RFC 3344 → 5944）标准化三部分：代理发现（代理周期发 ICMP 通告给出 COA，节点也可广播请求）、注册、间接选路。

7.7 切换与对上层的影响#

同子网与跨子网切换#

定义：换 AP 不换子网则 IP 不变、上层无感；跨子网须 DHCP 换址，会话中断。机制：①信号变弱开始扫描；②收到更强同名 beacon 后解除旧关联、关联新 AP；③交换机靠自主学习更新转发表；丢包源于转发表滞后形成的黑洞与断开窗口内缓存溢出。例：301 走到 305、两 AP 同子网，视频不断；跨楼换子网则中断需刷新。

对 TCP 的影响#

定义：无线丢包与切换丢包会让 TCP 误判拥塞而降吞吐。机制：TCP 把丢包与超时一律当拥塞——3 个重复 ACK 令 cwnd 减半，超时则 cwnd=1、ssthresh=cwnd/2 进慢启动；但无线丢包源于误码与切换，降窗纯属误判。对策：①本地恢复（链路层 ARQ）；②让 TCP 感知无线，只对拥塞性丢包降窗；③分离连接（主机—AP、AP—通信者两段）。例：信号弱时下载变慢，接上 Wi-Fi 立刻变快。

典型例题#

例题 1（CDMA 叠加与解码）#

题目：M=8，c_A=(+,+,+,+,-,-,-,-)，c_B=(+,+,-,-,+,+,-,-)，c_C=(+,-,+,-,+,-,+,-)；A 发 1、B 发 0、C 发 1，求叠加信号并解码。

解答：

  1. 验证正交：c_A· c_B=c_A· c_C=c_B· c_C=0，自内积均为 8。
  2. 编码（1 → +c，0 → -c）：A 发 (+,+,+,+,-,-,-,-)，B 发 (-,-,+,+,-,-,+,+)，C 发 (+,-,+,-,+,-,+,-)。
  3. 叠加：逐分量相加得 S=(1,-1,3,1,-1,-3,1,-1)。
  4. 解码：S· c_A=8⇒ 1，S· c_B=-8⇒ 0，S· c_C=8⇒ 1，全部正确。
  5. 讨论：若 A 误用 c_B，解 B 时两者的 ±8 叠加，判决必错——正交是多用户共存的前提；码片速率 = 8 × 比特率。

答：S=(1,-1,3,1,-1,-3,1,-1)，解出 1、0、1。

例题 2（CSMA/CA 与 CSMA/CD）#

题目：802.11 为何不用 CSMA/CD？由此产生哪些差异？

解答：

  1. 前提：CSMA/CD 依赖"边发边听"且"冲突能被发送方发现"，以太网基带总线、功率相当，成立。
  2. 无线否定：发射比接收强约 100 dB；隐藏终端使冲突发生在 AP 处；全双工射频太贵；帧须整帧发完。
  3. 差异：
维度 CSMA/CD CSMA/CA
冲突 边发边检测、即停 不检测，靠退避避免
时机 空闲立即发 空闲后还要 DIFS + 退避
可靠 无链路确认 SIFS 回 ACK、超时重传
隐藏终端 无此问题 RTS/CTS 缓解
  1. 退避意义：无线冲突损失整帧并阻塞他人，故先随机等待让竞争者错开。

答：无线无法在发送中检测冲突，只能以"退避 + ACK + 预约"替代"检测 + 中止"。

例题 3（RTS/CTS 时序）#

题目：A、C 互为隐藏终端且都能与 AP 通信，A 要发长帧，画时序并说明。

解答：

  1. 无预约失败： 
A : [DIFS][==== DATA(长帧) ====]        超时退避
C :       [DIFS][==== DATA(长帧) ====]  超时退避
AP:          × 信号在 AP 叠加，CRC 错，无 ACK ×
  1. 有预约成功： 
A : [DIFS][RTS]··[      DATA      ]··
AP:           [SIFS][CTS]··[接收]··[SIFS][ACK]
C : 听不到 RTS      |<---- NAV 沉默 ---->|
                   听到 CTS 即闭嘴
  1. 作用：RTS 声明时长；AP 用 SIFS 抢先广播 CTS（SIFS < DIFS）；C 听不到 RTS 却听到 CTS 而沉默；A 收 ACK 才算成功。
  2. 代价：开销约 RTS + CTS + 3 个 SIFS，短帧不划算；C 若连 CTS 也收不到则无效——只缓解，且加重暴露终端。

答：把冲突从长数据帧转移到短控制帧，代价是时延与开销。

例题 4（切换丢包与 TCP）#

题目：H1 以 cwnd=16 MSS、RTT = 100 ms、MSS = 1460 B 下载，从 AP1 漫游到 AP2（同子网），中断 300 ms，下行全丢。

解答：

  1. 丢包三处：断开窗口内 AP 缓存溢出；转发表滞后成黑洞；链路层重传目标失效。
  2. 切换前吞吐：16×1460×8/0.1≈1.87 Mbps。
  3. 丢中间包：3 个重复 ACK → 快速恢复，ssthresh=8、cwnd=8，吞吐降至约 0.93 Mbps。
  4. 丢尾包：无重复 ACK，等 RTO → cwnd=1、ssthresh=8，慢启动 1→2→4→8 需 3 个 RTT，再加约 1 s 超时。
  5. 跨子网更糟：DHCP 换址 + 注册期间隧道仍指旧 COA，中断数百毫秒至数秒。

答：丢包源于断开窗口与转发表滞后；TCP 视为拥塞而降窗（减半或归 1），吞吐台阶式下跌；缓解靠快速切换、移动 IP 预注册、TCP 感知无线。

易错点与辨析#

  1. 无线 ≠ 移动：前者指介质，后者指位置或子网改变。
  2. AP 有线端口无 MAC：故地址 3 是路由器接口的 MAC，不是 AP 的。
  3. 隐藏是"漏听"致冲突，暴露是"多听"致浪费，方向别写反。
  4. 不检测冲突 ≠ 不侦听：载波侦听仍在；SIFS < DIFS 才是 ACK/CTS 能插队的前提。
  5. 退避计数忙时冻结，不清零；只有失败重传才扩大 CW。
  6. 链路层 ACK ≠ TCP ACK：前者逐帧，后者端到端累计。
  7. RTS/CTS 不根治隐藏终端，也不解决暴露终端。
  8. 隧道不能改内层目的地址：外层才是 COA。
  9. 三角路由是固有缺陷，透明性方向别写反；且只有跨子网才换 IP。
  10. CDMA 解码要除以 M，只算内积得 ±8。

一页速记#

  • 四要素：无线主机、基站、无线链路、自组织网络（无基站，节点兼路由器）。
  • 四分类：单跳/多跳 × 有/无基础设施 → Wi-Fi、mesh、蓝牙、MANET/VANET。
  • 三难题：路径损耗、干扰、多径 → 距离短、BER 高 → 强 CRC + ARQ。
  • SNR：提功率降 BER；给定 SNR 选满足 BER 的最高吞吐物理层；移动时速率自适应。
  • CDMA：s=d· c，d=1/MS· c；正交码内积 0；码片率 =M× 比特率。
  • 架构与扫描：BSS = 站点 + AP；SSID 为网络名；11 个重叠信道（1/6/11）；被动等 beacon，主动发 probe，关联后 DHCP 取址。
  • CSMA/CA：空闲 → DIFS → 发；忙 → 退避（空闲递减、忙冻结）→ 归零发 → 等 ACK；超时扩窗重传。DCF 必支持，PCF 可选。
  • RTS/CTS：CTS 令隐藏终端按 NAV 沉默；短帧不用；只缓解不根治。
  • 帧地址：1 接收（无线侧）、2 发送（无线侧）、3 路由器接口、4 仅 ad hoc。
  • 蓝牙与蜂窝：802.15.1 的 1 主 7 从 piconet、时隙轮询 + 跳频；4G LTE 的 eNodeB + EPC、5G NR 的毫米波与大规模 MIMO。
  • 移动 IP：归属/外地代理、永久地址、COA；注册走 UDP 434；三件套为代理发现、注册、间接选路。
  • 选路对比：间接用三角路由换透明；直接路径优但不透明，再移动靠锚点两次封装。
  • 上层影响：无线丢包 + 切换丢包 → TCP 误判拥塞 → 降窗；对策为本地恢复、TCP 感知无线、分离连接。

8.1 安全目标与攻击类型#

8.1.1 四个安全目标#

结论：网络安全归结为机密性、完整性、可用性、真实性四项，教材另列可控性为第五项。

机制：机密性指只有发送者与指定接收者能"理解"内容，靠加密实现；完整性指报文未被修改、或被修改后能被发现（"能发现"即可，不要求阻止）；可用性指授权用户需要时能获得服务；真实性指双方能向对方证明身份，Bob 与 Alice 可以是人、DNS 服务器或 Web 服务器。

例：转账邮件被改写收款账号——内容仍看得懂，机密性未破、完整性已破；加密后读不懂，机密性有了，但密文被翻转一位仍是完整性被破。两者必须分别用加密与散列/签名保证。

8.1.2 被动攻击与主动攻击#

结论：被动攻击只观测不改动，难以检测但可预防；主动攻击改动数据或系统状态，难以预防但可检测。

机制：被动攻击不与数据流交互，没有可检测痕迹，只能靠加密与流量填充；主动攻击必然留下异常流量或状态，可依靠鉴别、序列号与入侵检测发现。

攻击 做什么 破坏 防御
窃听 在共享介质或中间节点复制报文 机密性 加密、交换式网络
流量分析 由频次、长度推断通信性质 机密性 流量填充、隧道封装
篡改 修改、插入、删除内容 完整性 MAC、数字签名

DDoS 耗尽带宽或资源 可用性 限速、清洗、SYN cookie
劫持 接管已有会话 真实性 TLS、序号随机化

例：SYN 洪泛中攻击者用伪造源地址发出海量 SYN，服务器为半开连接预留资源；伪造源地址让追查困难，故防御靠 SYN cookie 与上游清洗。

8.2 密码学基础与密码分析攻击#

8.2.1 术语、分类与柯克霍夫原则#

结论：明文是原始数据，密文是加密输出，密钥是加解密参数；设计密码与破译密码统称密码学。分类看密钥是否相同（对称/非对称）与明文处理方式（块/流密码）。

机制：柯克霍夫原则要求安全性只依赖密钥的保密，不依赖算法保密——公开算法承受全世界分析反而更可信，隐晦的安全一旦泄露便彻底失效。

例：DES 是对称块密码，RC4 是对称流密码，RSA 是非对称算法；AES 是公开征集选出的标准，自研"秘密算法"常在逆向工程后崩塌。

8.2.2 三类密码分析攻击#

结论：按分析者掌握的信息由少到多分为唯密文、已知明文、选择明文攻击，强度递增；安全系统必须能抵御选择明文攻击。

机制：唯密文只有密文与算法，是最不利情形；已知明文额外握有若干"明文—密文对"，可验证候选密钥或恢复映射；选择明文可自选明文取得对应密文，从而做差分、线性等统计。

模型 掌握的信息 强度
唯密文 密文 + 算法 最弱
已知明文 密文 + 明文密文对 中
选择明文 可自选明文取得密文 强
选择密文 可自选密文取得明文 最强

例：凯撒只有 25 种移位，唯密文穷举即破；单表替换密钥空间达 26!，但英文中 e、t、a 的频率会泄露映射，几十个字符即可恢复大半字母表。

8.3 对称密钥加密#

8.3.1 替换密码与换位密码#

结论：替换换字母不换位置，换位换位置不换字母；古典密码密钥空间看似大，却经不起统计分析。

机制：替换含凯撒（整体移位）、单表替换（任意映射表）、多表替换（按密钥字循环换表）；换位典型是列置换。二者都没打散明文的统计特征。

例：ATTACKATDAWN 凯撒移位 3 得 DWWDFNDWGDZQ，重复的 T 仍对应重复的 W，结构一眼可见。

8.3.2 块密码、缺陷与 CBC#

结论：块密码把 k 比特明文块映射为 k 比特密文块；直接建表不可行，逐块独立加密又会让相同明文块产生相同密文块，CBC 用于解决后者。

机制：建表需 2ᵏ 个表项，无法维护，实际用密钥驱动的伪随机置换（Feistel 或 SPN）近似。CBC 让每块密文依赖此前全部明文，只多传一个随机初始向量 IV：

$c(0)=IV, c(i)=K_S(m(i)\oplus c(i-1)), m(i)=K_S⁻¹(c(i))\oplus c(i-1)$

IV 须随机、不可预测并按序传输，一块出错会影响其后一块解密。

例：若 m(1)=m(2)，因 c(1)=K_S(m(1)\oplus IV)≠ c(2)=K_S(m(2)\oplus c(1))，两密文块不同；ECB 下二者相同，加密纯色位图仍能看出轮廓。

8.3.3 DES、3DES 与 AES#

结论：DES 用 56 比特密钥、64 比特分组、16 轮迭代，今天可被暴力破解；替代者是 3DES 与 AES。

机制：DES 每轮做相同的替换与换位，用由 56 比特主密钥派生的 48 比特子密钥，解密只是子密钥次序相反。3DES 用两密钥做 EDE：C=E_K1(D_K2(E_K1(P)))。用 EDE 而非 EEE 是为兼容单次 DES（令 K1=K2 即退化）；用两个密钥而非三个，因 112 比特已足够；不用两重 DES（EE），因中间相遇攻击只需找满足 E_K1(P₁)=D_K2(C₁) 的密钥对，代价降到 2⁵⁶。

算法 分组 密钥 轮数 现状
DES 64 56 16 淘汰
3DES 64 112/168 3×16 过渡
AES 128 128/192/256 10/12/14 主流

例：AES 用 SPN 结构（字节代换、行移位、列混合、轮密钥加），软硬件都高效；以现有算力估算，暴力搜索其密钥约需 149 万亿年。

8.4 非对称密钥加密#

8.4.1 RSA：密钥生成、加解密与互逆性#

结论：非对称加密中加密密钥公开、解密密钥私有，双方无需预先共享秘密；RSA 公钥为 (n,e)，私钥为 (n,d)。

机制：一对密钥须满足 D(E(m))=m，用于签名时还须满足 E(D(m))=m，且由公钥推私钥不可行。生成：选大素数 p,q，令 n=pq、z=\varphi(n)=(p-1)(q-1)；选 e 使 \gcd(e,z)=1；求 d 使 ed≡1\pmod z。加密 c=mᵉ mod n，解密 m=cᵈ mod n，要求 0<m<n，故长报文必须分块。

为何能互逆：由 ed=1+k\varphi(n) 与欧拉定理 m^\varphi(n)≡1\pmod n 得 cᵈ=mᵉᵈ=m·(m^\varphi(n))ᵏ≡ m\pmod n；\gcd(m,n)≠1 时由中国剩余定理同样成立。签名只是把密钥换个位置：s=mᵈ mod n，验证 sᵉ mod n=m。

例：p=5,q=11,e=3 时 n=55、z=40、d=27，m=8 加密得 c=17，解密回到 8，见例题 1。

8.4.2 Diffie–Hellman 密钥交换#

结论：DH 让双方在公开信道上协商出共享密钥，密钥本身从不传输。

机制：公开大素数 p 与 p 的原根 g；Alice 选 a 发 A=gᵃ mod p，Bob 选 b 发 B=gᵇ mod p，双方各算 s=Bᵃ=Aᵇ=gᵃᵇ mod p。窃听者只有 g,p,A,B，求 s 需解离散对数。DH 不鉴别身份，单独使用必被中间人替换公钥。

例：p=23,g=5,a=6,b=15 时 A=8、B=19、s=2，见例题 2。

8.4.3 混合加密与会话密钥#

结论：实际系统用非对称加密或 DH 分发一次性会话密钥，再用对称密钥加密数据。

机制：会话密钥一次一密，泄露只影响本次会话；长期私钥只在握手时露面。分发途径有三种：人工配置、KDC 签发、公钥加密或 DH 协商。

例：TLS 用服务器公钥加密 48 字节预主密钥；PGP 用接收方公钥加密邮件会话密钥；IPsec 用 IKE 协商 ESP 密钥。

8.5 报文完整性与数字签名#

8.5.1 密码散列函数#

结论：散列把任意长报文压成固定长短串作为"数字指纹"：MD5 输出 128 比特，SHA-1 输出 160 比特，SHA-256 输出 256 比特。

机制：须满足四条——易计算；给定 h 求 x 使 H(x)=h 不可行（单向）；给定 x 求 y≠ x 且 H(y)=H(x) 不可行（抗弱碰撞）；找任意碰撞对不可行（抗强碰撞）。满足前三条为弱散列函数，四条全满足为强散列函数；受生日悖论影响，n 比特摘要的碰撞强度仅约 2^n/2。

例：下载镜像后比对官网 SHA-256；MD5 与 SHA-1 已有实用碰撞，不能再用于签名与证书。

8.5.2 报文鉴别码 MAC 与 HMAC#

结论：MAC 是带密钥的散列值，能在共享密钥的双方间验证完整性与来源，但不提供不可抵赖。

机制：双方共享认证密钥 s，发送 (m,H(m\|s))，接收方重算比对。没有 s 时攻击者可自造 m' 并附 H(m') 冒充；标准实现是 HMAC：H((K\oplus opad)\|H((K\oplus ipad)\|m))。

例：Trudy 截获报文后把金额由 100 改成 10000，不知 s 就算不出新 MAC，Bob 一比对即发现。

8.5.3 数字签名#

结论：签名须满足三条：可鉴别发送方、发送方不可否认、接收方不可伪造；通用做法是用私钥加密报文摘要。

机制：发送方算 h=H(m)，用私钥得 s=hᵈ mod n，发送 (m,s)；接收方用发送方公钥算 h'=sᵉ mod n，与自己算的 H(m) 比较。只签摘要不签全文，是因为非对称运算慢、签名会随报文膨胀。签名不提供机密性。

例：发布者公布安装包与签名，用户用其证书公钥验签；即使下载站被攻破，攻击者没有私钥也伪造不出有效签名。

8.5.4 公钥认证：证书与 CA#

结论：公钥必须与身份可靠绑定，否则基于公钥的鉴别会被中间人瓦解；手段是 CA 签发的公钥证书。

机制：实体向 CA 提交身份证明，CA 验证后用自己的私钥对"主体 + 公钥 + 有效期 + 序列号"签名。单一 CA 有流量压力与单点失效，实际用分布式 PKI：多级 CA 成树、根 CA 公钥安全预置、CA 间可交叉认证；证书过期失效，也可被显式撤销，需查 CRL 或 OCSP。

例：Alice 请求 Bob 主页被 Trudy 截获，Trudy 返回假主页，其中"Bob 公钥"实为自己的；Alice 用它加密会话密钥，Trudy 解出后再用真 Bob 公钥转发，全程被破译——根源是公钥未认证。

8.6 端点鉴别#

8.6.1 ap1.0 到 ap3.1#

结论：鉴别协议每补一个漏洞就暴露新问题，主线是"声明 → 地址 → 口令 → 加密口令 → 不重数 → 公钥"。

协议 做法 被攻破的方式
ap1.0 声明"我是 Alice" 任何人都能声明
ap2.0 声明 + 源 IP 地址 IP 地址欺骗
ap3.0 发送明文口令 窃听后重放
ap3.1 发送加密口令 密文被原样重放
ap4.0 共享密钥加密 nonce 需预共享密钥
ap5.0 私钥加密 nonce 中间人攻击

例：Trudy 录下 Alice 的登录报文，其中无论是明文口令还是加密口令，稍后原样发给 Bob 都能通过，这就是重放。

8.6.2 ap4.0 与不重数#

结论：不重数（nonce）是协议生存期内只用一次的数，用挑战—响应保证新鲜性，从而抗重放。

Alice                          Bob
  |  ① "我是 Alice"             |
  |--------------------------->|
  |  ② R（一次性随机数）         |
  |<---------------------------|
  |  ③ E_K(R)                   |
  |--------------------------->|
  |        ④ 解出 R'，比较 R'=R ?

机制：Bob 每次发新 R，Alice 必须用共享密钥加密送回，旧密文对不上新挑战；代价是须预共享对称密钥。若让 Alice 自己选随机数，Trudy 仍可重放，故随机数必须由验证方生成；用时间戳替代 nonce 也可，但要求时钟同步。

例：Trudy 重放昨天的 E_K(R_old)，Bob 今天发的是 R_new，解密结果不符，鉴别失败。

8.6.3 ap5.0 与中间人攻击#

结论：ap5.0 用公钥代替共享密钥，但若不验证公钥归属，就会被中间人同时欺骗双方。

Alice            Trudy                     Bob
  |                 |  ① "我是 Alice"        |
  |                 |---------------------->|
  |                 |  ② R                   |
  |                 |<----------------------|
  | ③ R             |                        |
  |<----------------|                        |
  | ④ E_dA(R)       |  ⑤ E_dT(R)             |
  |---------------->|----------------------->|
  |                 |  ⑥ 索要公钥，回 E_T     |
  |                 |<---------------------->|

机制：Bob 发 R，Alice 用私钥加密送回，Bob 再取公钥验证 E_A(E_d_A(R))=R；漏洞在于 Bob 无从确认拿到的公钥真是 Alice 的。

例：Trudy 向 Bob 扮演 Alice、向 Alice 扮演 Bob，双方都"验证通过"，实际各自与 Trudy 建会话，此后报文全被读取改写。修法只有一个：用证书认证公钥。

8.7 密钥分发与 KDC、Kerberos#

结论：n 个用户两两通信需 O(n²) 个主密钥，不可行；引入可信第三方 KDC 为每次会话签发一次性会话密钥。

机制：每个用户只与 KDC 共享一个主密钥。Alice 要与 Bob 通信，向 KDC 请求，KDC 生成会话密钥并分别用两人主密钥加密下发，之后不参与。Kerberos 是其实用系统：分 AS 与 TGS，登录得票据授予票据 TGT，凭 TGT 换服务票据，访问时提交票据与带时间戳的鉴别符，实现单点登录。

例：1000 名员工两两通信需约 50 万密钥，用 KDC 只需 1000 个主密钥；上午登录域后访问文件、邮件、打印服务器均不再输口令。代价是单点失效、密钥集中风险与时钟同步要求（通常容忍 5 分钟偏差）。

8.8 传输层安全：TLS/SSL#

8.8.1 组成与握手四阶段#

结论：TLS 位于应用层与 TCP 之间，提供机密性、完整性与服务器鉴别（客户鉴别可选），由握手、更改密码规格、警报、记录四个子协议组成；握手分四阶段。

客户端                                  服务器
  | ① TCP 三次握手                        |
  |   ClientHello：版本、套件列表、Rc      |
  |-------------------------------------->|
  |   ServerHello：选定套件、Rs、证书      |
  |<--------------------------------------|
  | ② 验证证书链取公钥，生成 PMS 并加密      |
  |-------------------------------------->|
  | ③ 由 PMS、Rc、Rs 导出主密钥与会话密钥   |
  | ④ Finished（此前握手报文的 MAC）        |
  |<------------------------------------->|
  |    切换到加密记录层，传输应用数据        |

机制：①协商版本、算法与客户端随机数 R_c；②服务器出示证书与 Rₛ，客户端检查 CA 是否可信、验证证书取公钥，必要时回送客户证书；③客户端生成 48 字节预主密钥用服务器公钥加密，双方导出密钥；④Finished 覆盖此前全部握手报文，确认未被篡改与降级。

例：若没有 Finished，中间人可删掉高强度套件把双方降级到弱算法；因 MAC 覆盖协商内容，删改必被发现。

8.8.2 密钥导出与记录协议#

结论：一次握手导出四个密钥：两个方向各一个加密密钥与一个 MAC 密钥；记录协议逐条加密并附加 MAC。

机制：由预主密钥、R_c、Rₛ 经伪随机函数导出主密钥再扩展；两个随机数保证每次会话密钥不同，TLS 1.3 用临时 DH 实现前向保密。MAC 输入包含记录序号，因而能发现重排、重放与删除；关闭连接须发 close_notify，防止截断攻击。

记录字段 作用
类型 握手、警报、更改密码规格、应用数据
版本/长度 协议版本与载荷长度
数据 上层报文分片（加密）
MAC 覆盖序号、类型、版本、长度与数据

例：攻击者重发一条已加密的转账记录，序号不匹配导致 MAC 校验失败，服务器直接丢弃。

8.9 网络层安全：IPsec#

8.9.1 组成、SA 与 AH/ESP#

结论：IPsec 把安全机制下沉到 IP 层，由安全协议（AH、ESP）与密钥管理协议（IKE）组成，二者通过安全关联 SA 绑定。

机制：IPv4 设计时未考虑安全，缺少身份鉴别与数据保护。SA 是双方对"协议、模式、算法、密钥、生存期"的协定，由 32 比特 SPI 标识；SA 单向，双向通信需两个；状态存于安全关联数据库，故 IPsec 有状态、有连接。AH 提供源认证与完整性但不加密；ESP 另加机密性，头含 SPI 与递增序号（抗重放），尾含填充与下一首部，鉴别码覆盖头、载荷与尾。

例：只要求"确认来自合法网关且未被改动"可用 AH；要求"内容也不能被看到"必须用 ESP，故 ESP 应用更广。

8.9.2 传输模式与隧道模式#

结论：传输模式只保护 IP 载荷，插在原始 IP 头与传输层头之间；隧道模式把整个原始 IP 包封装进新 IP 包，保护范围更大。

传输模式：[ IP 头 ][ AH/ESP ][ 传输层头+数据 ][ ESP 尾 ]
隧道模式：[ 新 IP 头 ][ AH/ESP ][ 原 IP 头 ][ 传输层头+数据 ][ ESP 尾 ]

机制：传输模式用于主机到主机，路由器按原始 IP 头转发、开销小；隧道模式用于网关到网关，外层地址是隧道端点，内网地址与协议全部隐藏，还能把多条流聚合成一个加密流。ESP 隧道模式下原始 IP 头也被加密且被鉴别码覆盖，兼具起源鉴别与流量机密性。

例：远程员工拨入可用传输模式；站点互连用隧道模式，内网主机无需装 IPsec。与 NAT 对比：NAT 靠隐藏地址让外部看不见，IPsec 靠加密整包让外部看不懂也改不了，角度不同可叠加。

8.10 无线局域网安全：WEP 与 WPA#

8.10.1 WEP 的设计与缺陷#

结论：WEP 已完全不安全；问题不在 RC4，而在 IV 太短且明文传输、完整性校验可伪造、没有密钥管理与双向鉴别。

机制：WEP 用 RC4 生成密钥流与明文逐位异或，密钥由 40/104 比特共享密钥加 24 比特 IV 组成，IV 随帧明文传输，完整性用 CRC-32。24 比特 IV 仅约 1677 万取值，繁忙网络几小时即重复；IV 重复则密钥流重复，两条密文异或即得两条明文异或。CRC-32 是线性的，攻击者无需密钥即可翻转密文并同步修补校验值；此外只有终端向 AP 的单向鉴别，密钥靠手工配置且极少更换。

例：收集足够多 IV 重复的帧即可离线恢复密钥（FMS/PTW 类方法），随后注入任意报文，加密、完整性、接入控制同时失效。

8.10.2 WPA 与 WPA2#

结论：WPA 用 TKIP 临时补救，WPA2 用 AES-CCMP 彻底替换，并用四次握手导出会话密钥。

机制：TKIP 仍用 RC4，但为每帧派生不同密钥、加序号防重放、用 Michael 做完整性；WPA2（802.11i）改用 AES-CCMP 把加密与认证合一，通过四次握手从预主密钥导出会话密钥，企业级用 802.1X 为每个用户单独认证发密钥。

例：家用路由器"WPA2-PSK"由口令派生 PMK 再经四次握手生成每会话密钥；企业则用 RADIUS 服务器逐用户认证。

8.11 防火墙与入侵检测系统#

8.11.1 三类防火墙#

结论：防火墙在可信内网与不可信外网之间执行访问控制，放行某些分组、阻断另一些，分为无状态过滤、状态检测、应用网关三类。

机制：需要防火墙是为阻止 DoS、阻止内容被非法修改、只允许授权访问。无状态过滤器逐包独立检查 IP/TCP/UDP 头（源/目的地址与端口、ICMP 类型、SYN 与 ACK 位），按 ACL 自上而下匹配，命中即执行；丢弃进入的 ACK=0 分段可阻止外部发起连接而保留内网发起，丢弃协议号 17 或端口 23 可阻断 UDP 与 telnet。但它会放行"不合理"分组——伪造 ACK=1 即可穿过。

类型 依据 优点 缺点
无状态过滤 单个分组头部 快、简单 无法关联会话
状态检测 连接状态表 + 头部 只放行合法回程 不懂应用层
应用网关 应用层数据 可按用户授权、可审计 慢、每应用一个

例：内网主机访问外部网站，状态表记下该连接，外部返回的 ACK=1 分组因属于已建连接被放行；外部凭空发来的 ACK=1 分组查不到连接，被丢弃。

8.11.2 应用网关、局限与 IDS#

结论：应用网关检查应用层数据、可按用户授权；但防火墙整体有局限，需 IDS 补位。

机制：以允许特定用户 telnet 外部主机为例：所有 telnet 用户先连网关，网关对授权用户建立到目的主机的第二条连接并中继，过滤器阻断一切非源自网关的 telnet 流量。局限有五条：无法验证源地址真伪（IP 欺骗）、每个被代理应用都要单独网关且开销大、对用户不透明、对 UDP 只能全放或全禁、挡不住针对 Web 站点本身的攻击。

例：IDS 做深度包检测并关联多个分组，能发现端口扫描、拓扑探测与 DoS；基于特征的 IDS 只能识别已知攻击，匹配成功也可能误报，特征库庞大时还会因过载漏检，IPS 则在检测后直接阻断。

典型例题#

例题 1：RSA 取小素数求密钥并加解密#

题目：取 p=5、q=11、e=3，明文 m=8，求公私钥并加解密。

解：

  1. n=pq=5×11=55。
  2. z=(p-1)(q-1)=4×10=40。
  3. 校验 \gcd(3,40)=1 且 3<55，故 e 可用。
  4. 解 3d≡1\pmod40：3×27=81=2×40+1，取 d=27。公钥 (55,3)，私钥 (55,27)。
  5. 加密：c=8³ mod 55=512 mod 55=17。
  6. 解密：17²⁷ mod 55。因 17²≡14、17⁴≡31、17⁸≡26、17¹⁶≡16，且 27=16+8+2+1，故 17²⁷≡16×26×14×17≡31×14×17≡49×17≡8，还原 m=8。
  7. 拓展：同一密钥对签名，s=8²⁷ mod 55。由 8²≡9、8⁴≡26、8⁸≡16、8¹⁶≡36，得 s≡36×16×9×8≡2，验证 sᵉ=2³=8=m。

点评：务必检查 m<n，否则先分块；d 是 e 关于 z 的模逆而非倒数。

例题 2：Diffie–Hellman 小数字交换#

题目：p=23、g=5，Alice 私钥 a=6，Bob 私钥 b=15，求双方公钥与共享密钥。

解：

  1. A=5⁶ mod 23：因 5²≡2、5⁴≡4，得 A≡4×2=8。
  2. B=5¹⁵ mod 23：因 5⁸≡16，得 B≡16×4×2×5≡18×2×5≡13×5≡19。
  3. Alice 算 s=19⁶ mod 23：19²≡16、19⁴≡3，得 s≡3×16=48≡2。
  4. Bob 算 s=8¹⁵ mod 23：8²≡18、8⁴≡2、8⁸≡4，得 s≡4×2×18×8≡2。
  5. 双方都得 s=2，经 KDF 处理后作会话密钥。

点评：g 必须是原根，否则子群太小；DH 不鉴别身份，必须配证书或签名。

例题 3：签名 + 加密的完整流程与钥匙配对#

题目：Alice 向 Bob 发送转账指令 m，要求保密、可鉴别、可验证完整性、防抵赖，写出流程并标明每步用谁的哪把钥匙。

解：

  1. Alice 算摘要 h=H(m)。
  2. Alice 用自己的私钥 d_A 签名 s=h^d_A mod n_A。
  3. Alice 生成会话密钥 K_S，对称加密 c=E_K_S(m\|s)。
  4. Alice 用Bob 的公钥 e_B 加密会话密钥 k=K_S^e_B mod n_B。
  5. 发送 (c,k)，可附自己的证书。
  6. Bob 用自己的私钥 d_B 解出 K_S，用 K_S 解出 (m,s)，再用Alice 的公钥 e_A 验证 s^e_A mod n_A=H(m)。
操作 用谁的钥匙 目的
加密会话密钥 Bob 公钥 只有 Bob 能取回 K_S
解出会话密钥 Bob 私钥 恢复 K_S
生成签名 Alice 私钥 别人无法伪造
验证签名 Alice 公钥 含第三方在内均可验证

常见错误配对：①用 Alice 公钥加密给 Bob，只有 Alice 私钥能解，Bob 打不开；②用 Bob 私钥"签名"，署名者成了 Bob；③只加密不签名，Alice 可抵赖；④只签名不加密，金额明文可见。

点评：加密看接收方公钥，签名看发送方私钥。先签名后加密使签名与明文语义绑定，第三方也能核验原文。

例题 4：ap3.0/ap4.0 重放攻击推演#

题目：Alice 用口令登录 Bob 的服务器，Trudy 与其同网段，分别推演 ap3.0、ap3.1、ap4.0 下能否冒充。

解：

ap3.0：① Alice→Bob："我是 Alice"，口令 s3cr3t
        ② Trudy 嗅探并保存
        ③ 稍后 Trudy→Bob 原样重发  → 鉴别通过
ap3.1：口令加密后发送，Trudy 解不开，但可原样重放该密文 → 仍通过
ap4.0：① Bob→Alice：R1
        ② Alice→Bob：E_K(R1)        → 通过
        ③ Trudy 重放旧 E_K(R0)，R0≠R1 → 解密得 R0，失败

结论：ap3.0 与 ap3.1 都挡不住重放，因为报文可被复用；ap4.0 用 nonce 强制每次交互不同，旧报文失效。

点评：随机数必须由验证方生成；用时间戳也能抗重放，但要求时钟同步，这正是 Kerberos 容忍 5 分钟偏差的原因。

例题 5：HMAC 与数字签名的区别#

题目：服务器之间传对账文件、向客户发布安装包，各应选 HMAC 还是数字签名？

维度 HMAC 数字签名
密钥 双方共享对称密钥 私钥签名、公钥验证
第三方可验证 不能 能
防抵赖 不能，双方都能算 能
性能 快，适合大流量 慢，只签摘要
前提 需安全分发共享密钥 需 PKI 与证书

解：判断三步——①双方能否共享密钥；②是否需向第三方证明或防抵赖；③数据量与性能是否敏感。对账文件在可信双方之间、流量大，用 HMAC；安装包面向不特定客户、需公开验证与防抵赖，用数字签名。

点评：两者都提供完整性与来源鉴别，差别在信任模型而非算法强度；TLS 既用证书签名完成握手鉴别，又用 MAC/AEAD 保护每条记录。

易错点与辨析#

  1. 加密 ≠ 鉴别：接收方能解密只说明"持有密钥"，不能证明是哪个持有者。
  2. 加密 ≠ 抗重放：ap3.1 证明密文可原样重放，抗重放只能靠 nonce、时间戳或序号。
  3. 签名用私钥、验签用公钥；加密用对方公钥、解密用自己私钥。
  4. 签名不提供机密性，签名报文仍是明文。
  5. MAC 不防抵赖：双方共享密钥，第三方无法判断是谁算的。
  6. 散列不是加密：不可逆、无密钥（HMAC 除外），不能"解密"。
  7. MD5/SHA-1 已有碰撞，不能再用于签名与证书。
  8. CBC 的 IV 不必保密，但必须随机不可预测；IV 复用等于泄露明文关系。
  9. DES 有效密钥 56 比特，64 比特分组中的 8 比特是奇偶校验位。
  10. 3DES 用 EDE 是为兼容单 DES；两密钥 3DES 强度约 112 比特，不是 168 比特。
  11. RSA 要求 m<n，d 是模逆不是倒数，e 与 \varphi(n) 必须互质。
  12. DH 不提供认证，它只是密钥交换，本身不传数据。
  13. ap5.0 的漏洞是公钥没认证，不是公钥算法不安全，修法是证书。
  14. AH 不加密；隧道模式更安全但多一层 IP 头、开销更大。
  15. SA 是单向的，双向通信需两个 SA。
  16. WEP 的 CRC-32 不是密码学校验，可被同步篡改；问题不是 RC4 弱，而是 IV 复用与无密钥管理。
  17. 防火墙 ≠ IDS：防火墙按规则放行阻断、逐包看头部；IDS 做深度检测与跨包关联，只告警（IPS 才阻断）。
  18. 隧道模式下原始 IP 头既被加密也被鉴别码覆盖，故 ESP 隧道模式同时提供机密性与起源鉴别。

一页速记#

  • 四目标：机密性（加密）、完整性（散列 + MAC/签名）、可用性（防火墙/IDS）、真实性（nonce + 证书）。
  • 攻击：被动＝窃听、流量分析；主动＝篡改、重放、伪造、DoS、劫持。
  • 密码分析：唯密文 < 已知明文 < 选择明文；安全性只依赖密钥（柯克霍夫）。
  • 对称：DES 56/64/16 轮；3DES＝EDE、两密钥 112 比特；AES 128 分组、128/192/256 密钥、10/12/14 轮。
  • CBC：c(i)=K_S(m(i)\oplus c(i-1))，c(0)=IV。
  • RSA：n=pq、z=(p-1)(q-1)、ed≡1\pmod z；c=mᵉ、m=cᵈ；签名 s=mᵈ、验证 sᵉ=m。
  • DH：A=gᵃ、B=gᵇ、s=gᵃᵇ，不认证。
  • 混合加密：非对称送会话密钥，对称运数据。
  • 完整性：MD5 128、SHA-1 160、SHA-256 256；MAC＝H(m\|s)；签名＝私钥加密摘要。
  • 认证：CA 证书绑定身份与公钥；PKI 多级；CRL/OCSP 撤销。
  • 鉴别：ap1.0 声明、ap2.0 IP、ap3.0 口令、ap3.1 加密口令（均可重放）→ ap4.0 nonce → ap5.0 中间人 → 证书。
  • KDC：主密钥 + 会话密钥票据；Kerberos＝AS + TGS + TGT + 时间戳窗口。
  • TLS：四阶段（协商、鉴别与密钥交换、密钥导出、Finished）；记录＝类型/版本/长度/数据/MAC。
  • IPsec：AH 只鉴别、ESP 加密 + 鉴别；传输模式护载荷、隧道模式护整包；SA 单向；ESP + 隧道最常用。
  • WEP：RC4 + 24 比特 IV + CRC-32，IV 复用、校验可伪造；WPA（TKIP）→ WPA2（AES-CCMP + 四次握手）。
  • 防火墙：无状态过滤 → 状态检测 → 应用网关；局限是 IP 欺骗、每应用一网关、UDP 粗放。
  • IDS：深度包检测 + 跨包关联，查端口扫描、拓扑探测、DoS；特征法有误报漏报与过载。

7. 计算模板#

7.1 CRC（模 2 除法）#

  1. 设生成多项式 G(x) 对应 r+1 位，则冗余位为 r 位。
  2. 数据后补 r 个 0，用模 2 除法除以 G 对应的比特串。
  3. 余数（补足 r 位）即为 CRC，接在数据后发送。
  4. 接收端用同样方法除，余数为 0 则未检出错误（不保证无错）。

7.2 IP 分片#

  1. 每片数据部分必须是 8 的倍数（除最后一片）。
  2. 片数 =⌈数据部分长度/(MTU-20)⌉。
  3. 片偏移 = 该片数据起点 / 8。
  4. 除最后一片外，MF=1；同一数据报各片标识相同。

7.3 子网划分#

  1. 需要 k 个子网 → 借位 s=⌈\log₂ k⌉，新前缀 =24+s（以 /24 为例）。
  2. 每个子网地址块 =2^32-新前缀，从原网络地址起按块大小递增。
  3. 子网内可用地址 = 去掉网络地址与广播地址。

7.4 TCP 序号与吞吐#

  • 第 n 个报文段首字节序号 = 初始序号 + 之前已发送字节数。
  • 确认号 = 已连续收到的最后一个字节序号 + 1。
  • 窗口 W、RTT 已知时，最大吞吐量 =W/RTT。

9. 考前 60 秒判断清单#

  • 链路层单位是帧，网络层单位是分组；不是每个子网都有 DHCP 服务器。
  • 并非每个 CIDR 地址块都是一个子网；路由器转发表由域内 + 域间协议共同配置。
  • 数字签名是非对称的；CRC 检错能力取决于生成多项式。
  • IPv4 首部"标识"字段用于分片重组；IPv6 不分片、首部定长。
  • NAT 能缓解 IPv4 地址不足，根本原因是转发时主要看目的网络。
  • 最长前缀匹配不能降低路由查找的时间复杂度。
  • 同一 IP 地址在不同子网掩码下网络地址可能不同。
  • 路由器不转发链路层广播，交换机泛洪广播帧。
  • 交换机每个端口是独立冲突域，但不隔离广播域。
  • CSMA 不能完全避免冲突，适合小规模广播网络；CSMA/CD 用于有线以太网。
  • 802.11 的 MAC 不检测冲突（无法边发边听），用 CSMA/CA + ACK；RTS/CTS 解决隐藏终端，但不保证不碰撞。
  • BSS 与 LAN 没有必然关系，取决于组网方式；AP 不转发同一 BSS 内终端之间的帧。
  • 4G/5G 是"单跳 + 有基础设施"；自组织网络无基站，节点兼作路由器。
  • IPsec 隧道模式下整个原始 IP 包被加密封装进新 IP 包。
